# СЛОВО 2.0 — свод правил проекта

**Назначение.** Единый, исчерпывающий справочник по правилам ведения проекта:
как устроен контент (слова и их разметка), как оформлены карточки и картинки,
как подаётся учебный материал, как выпускается релиз и что именно нельзя
ломать. Составлен по полному аудиту репозитория (2026-11-09) и закрывает
подготовку работы со словарием **5 класса**
([`proposals/slova-5-klass.md`](./proposals/slova-5-klass.md)).

**Состояние проекта на момент составления:** версия `0.90.1` (в этом коммите —
патч `0.90.2`), 1–4 класс наполнены, картинок 257 из 257 (100 %).

**Состояние на 2026-11-10 (`0.92.0`):** наполнены классы 1–5; в банке 367 карточек;
у 5 класса картинок пока нет — показывают эмодзи, партии генерируются после релиза.
Письменные задания понимают и требуют заглавную в именах собственных («Москва»,
«Родина», «Россия», «Жостово»): на клавиатуре есть «⇧», без большой ответ не засчитывается.
«Собери слово» — настоящий перенос карточек (обмен между лунками, без вставки);
в нижнем меню вкладка «Игры» (6 пунктов): «Свободная практика» — сборка слов,
которые ребёнок уже встречал, без XP и без SRS; «скоро»-карточки помечены честно.

**Как пользоваться.**

1. Каждый раздел снабжён ссылкой, *где правило проверяется*: скрипт
   (`scripts/*.mjs`), тест (`tests/*.ts(x)`) или документ (`docs/...`).
2. Источники истины — **код и скрипты**, этот документ вторичен. Если они
   расходятся, верить коду; сам документ в таком случае правится в том же PR
   (правило «документ не врёт»).
3. Разделы 4–8 — рабочий материал для контент-задач (5 класс). Разделы 3 и 9 —
   обязательные для любого PR, включая документационные.

## 1. Проект в двух словах

| Что | Как устроено |
|---|---|
| Продукт | Мобильное обучающее **офлайн-PWA** для тренировки словарных слов русского языка (дети, УМК «Школа России», 1–4 класс) |
| Стек | React 18 + Vite 5 + zustand + IndexedDB (`idb`) + vite-plugin-pwa (workbox, precache) + TypeScript strict |
| Хостинг | GitHub Pages, база `/slovo2/` (в `vite.config.ts`, `REPO_BASE`); деплоится только `main` после мерджа PR |
| Данные | Нет бэкенда для учебной части: весь прогресс в IndexedDB профиля; пилотный API классов и телеметрии живёт в `server/` и в сборку PWA **не входит** |
| Контент | Один общий банк слов (`src/content/words.ts`, 367 карточек); **класс — свойство профиля** (`Profile.activeClass`), а не свой пак |
| Уроки | Тематические блоки по 4–8 слов; 5 уроков (1 класс) + 16 (2) + 13 (3) + 15 (4) + 22 (5) = 71 урок |

| Учебная методика | LOOK–SAY (знакомство → проговаривание → закрепление → извлечение), SRS (упрощённый SM-2), интерливинг, отработка ошибки (см. §6) |

Главные цифры (сверять перед каждым релизом класса):

* карточек в банке: **367** (`WORDS.length`);
* слов по классам: **30 / 94 / 72 / 94 / 127** (`tests/content.test.ts`, таблица `EXPECTED`);

* файлов картинок: **257** (`npm run images:report`; у 5 класса — 0, покрытие 70 %);
* сборка ≤ ~12 МБ на файл в precache (`maximumFileSizeToCacheInBytes`).

## 2. Нерушимые правила проекта

Эти правила нельзя нарушать ни одним PR без отдельного решения владельца
проекта. Большинство из них — следы реальных инцидентов.

1. **`id` слова стабилен навсегда.** Схема: если слово входит в программу
   2 класса — исторический `g2_<текст>`, иначе `g<первый класс>_<текст>`.
   `profile.words` в сохранениях детей ключуется по `id`; правка схемы
   = потеря прогресса у всех. Префикс — **имя, а не фильтр класса**
   (`GRADES_OF` — фильтр). Подтверждается `tests/content.test.ts`
   (проверка префиксов) и README.
2. **Смена класса меняет ровно два поля:** `activeClass` и `adaptiveGood: 0`.
   Опыт, кристаллы, серия, заморозки, достижения, дни, покупки, пазлы,
   сундуки, тюнинг, музыка, звуки, мечты, уровни уроков других классов,
   журнал — не трогаются никогда. Запрещённые в этом сценарии операции:
   `newProfile`, `resetProfile`, `replaceAll`, `restoreSnapshot`, `touchDay`.
   (`src/state/store.ts`, §8.1 ниже; тест — `tests/classes.test.ts`.)
3. **Одно слово — одна карточка и один прогресс на все классы.** Общие для
   двух словарей слова («обед», «тарелка», «грамм», «килограмм», «интересно»)
   существуют в банке один раз и получают `grades: [a, b]`.
4. **Озвучка и аудиофайлы слов не добавляются.** Вместо слухового диктанта —
   зрительный («показать → закрыть → написать»). Стоп-лист, зафиксирован
   в README и `classes-1-4.md` §10.7.
5. **«е» вместо «ё» при письме засчитывается** как верный ответ
   (`sameTypedWord` в `src/engine/word-facts.ts`); обратная замена — ошибка.
   В заданиях с выбором буквы «ё» остаётся единственно верной.
5a. **Имя с заглавной пишется с заглавной — и при вводе, и в отображении.**
   В банке это «Москва», «Родина», «Россия», «Жостово» (+ фразы с заглавными,
   которые в вводе не участвуют). На экранной клавиатуре есть «⇧»: один тап —
   заглавная на следующую букву, двойной — все заглавные; «е» за «ё»
   засчитывается и с заглавной. Если в цели есть заглавная, ответ без неё
   **не засчитывается**. Слова с пробелами в письменные задания не попадают
   (классы с клавиатурой их исключают — `safeKind`). Проверяется в
   `tests/typing-ui.test.tsx` (юнит и живой проход с клавиатуры).
6. **Картинка не имеет права выдавать написание слова:** ни букв, ни цифр,
   ни надписей, ни «ценников». Один предмет, по центру, плоский стиль пака.
7. **Слово без картинки — это эмодзи-плита, а не пустая рамка** (`WordArt`,
   класс `.word-art-frame.no-image`). UI не показывает «недоделанные» карточки.
8. **Существующий контент 1–4 классов (94 строки 2 класса, 163 карточки
   3–4 класса) не правится** ради 5 класса и любых других задач. Любая
   правка проверенных строк RAW — отдельное решение и отдельный релиз.
9. **Ничего не «переезжает» молча.** Добавление класса, поля или проверки
   обязано показать себя в `tests/content.test.ts`, `tests/stress-snapshot.ts`
   и релизной заметке. Ошибка контента должна падать **на импорте контента**,
   а не в уроке у ребёнка.
10. **Документация не врёт.** Если этот файл и код расходятся, верить коду;
    документ правится в том же PR, что и код.

## 3. Репозиторий и процесс разработки

### 3.1. Ветки и коммиты

* Рабочая ветка текущей сессии — **`arena/2f2152a3-slovo2`**. Все изменения,
  коммиты и push — только в неё (`git push origin arena/2f2152a3-slovo2`);
  переназывать её нельзя. PR открывается из этой ветки в `main`.
* `main` получает изменения только через PR; GitHub Pages деплоит только `main`.
  Открытый PR не меняет версию на сайте.
* Коммиты — атомарные; крупные контентные партии (картинки) приходят партиями
  по ≤3 кадра с немедленным проведением в контент.

### 3.2. Версионирование (обязательно для КАЖДОГО PR, включая документацию и CI)

* Номер релиза — `version` в `package.json`. **Каждый PR в `main` увеличивает
  версию.** Исключений «без релиза» нет. Мелкие изменения — patch
  (`0.90.1 → 0.90.2`), крупные — minor/major.
* `package-lock.json` содержит **два** совпадающих значения: поле `version`
  на верхнем уровне и `packages[""].version`. При `npm version X.Y.Z
  --no-git-tag-version` они синхронизируются; правка руками — в обеих точках.
* Каждая сборка помечается коротким SHA коммита (суффикс `-dirty` при
  незакоммиченных изменениях); виден в меню ☰ (`СЛОВО 2.0 · версия X.Y.Z`) и
  в «Родителям → Приложение».
* Правило проверяется `npm run release:check` (`scripts/release-check.mjs`):
  требует строго большего, чем в `origin/main`, номера версии; совпадения
  lock; наличия заметки `docs/RELEASE-<версия>.md`; заголовка PR, начинающегося
  с `v<версия> — ` (проверяется при заданном `PR_TITLE`).

### 3.3. PR: заголовок, шаблон, CI

**Заголовок PR** начинается с `v<версия> — краткое описание`
(пример: `v0.30.0 — 4 класс: 94 слова, 15 уроков`).

**Описание PR** заполняется по шаблону `.github/pull_request_template.md`:
секции «Релиз» (версия, заголовок, заметка, ссылка на `?diag=1`),
«Что изменено» (1–3 предложения), «Проверки» (чек-лист команд).

**CI** (`.github/workflows/check.yml`) на каждый PR гоняет полный контур:
`test:release` → `release:check` (с `PR_TITLE` из заголовка PR) → `npm ci` →
`audio:check` → `typecheck` → `content:check` → `test:content` →
`test:adaptive` → `server:test` → `test:smoke` → `test:galleries` →
`test:guard` → `test:icons` → `test:contrast` → `build` → `test:boot`.
PR с красным CI не мерджится. Если другой PR уже повысил версию в `main` —
обновите свою версию и повторите проверки.

### 3.4. Полный локальный контур перед PR (в этом порядке)

| # | Команда | Что ловит |
|---|---|---|
| 1 | `npm run test:release` | Валидация правила версий (юнит-тест самой проверки) |
| 2 | `git fetch origin main && PR_TITLE="vX.Y.Z — …" npm run release:check -- origin/main` | Версия > main, lock согласован, заметка есть, заголовок верный |
| 3 | `npm run typecheck` | TypeScript strict, `tsc --noEmit` |
| 4 | `npm run content:check` | Разметка слов: ударения, слоги, опасные буквы, падежи, мнемоники, подсказки, картины (§4) |
| 5 | `npm run test:content` (`tests/content.test.ts` + `tests/stress.test.ts`) | Связность классов/уроков/слов; снимок ударений (§4.12) |
| 6 | `npm run test:adaptive` | Движок адаптации и аудит орфограмм всех слов |
| 7 | `npm run test:smoke` (включает `tests/classes.test.ts` и 900+ проверок UI) | Урок проходится, награды начислены, смена класса не трогает прогресс |
| 8 | `npm run audit:storage` | Сейф прогресса: копии, корзина, сбои записи |
| 9 | `npm run build` | Прод-сборка (`tsc -b && vite build`) |
| 10 | `npm run test:boot` | Прод-бандл на первом запуске не даёт пустой экран |

Дополнительно, по обстоятельствам: `npm run audio:check` (музыка/звуки),
`npm run demo:check` (макеты магазина), `npm run test:guard` (защита покупок),
`npm run test:icons`, `npm run test:contrast` (темы), `server:test`
(пилотный API), `npm run images:report [-- --strict]` (покрытие картинками),
`npm run test:galleries` (галереи товаров), `npm run test:qr` (вручную).

**Замечание про «зелёный контур ≠ готово».** Успешные
`typecheck`/`build`/`test:smoke` не гарантируют ни визуальной приёмки
контента, ни того, что словари сверены с учебником. Вычитка человеком
обязательна (§4.13).

### 3.5. Документация

* `docs/RELEASE-<версия>.md` — заметка релиза. Структура: что сделано
  (списком/таблицей), как подготовлен контент (если применимо), проверки
  (списком команд), «Дальше». Пример уровня детализации —
  `docs/RELEASE-0.30.0.md` (4 класс) и `docs/RELEASE-0.52.0.md` (картинки).
* `docs/proposals/` — предложения и планы работ (архитектура классов,
  словники, картинки, магазин). Большие изменения проходят через документ
  со статусом «ПРИНЯТО» до реализации.
* `docs/PLAN.md` — хронологический журнал и «Открытая очередь»;
  `docs/HANDOFF.md` — точка передачи контекста между сессиями.
* Этот файл — `docs/PROJECT-RULES.md` — единый свод правил; изменения правил
  проекта вносятся туда в том же PR.

## 4. Контент: формат слова и правила разметки

### 4.1. Строка контент-пака (`src/content/words.ts`, блок `RAW`)

```
слово|ударение(индекс)|слоги|опасные_буквы|тип|эмодзи|предложение с ____|подсказка|мнемоника?|картинка?
```

* 9 обязательных полей + необязательное 10-е (картинка). Пустое 10-е поле =
  «картинки нет, показываем эмодзи». Пустое 9-е (мнемоника) допустимо.
* Разделитель — `|`. Ошибки в разметке валятся **при импорте контента**
  (`parse()` бросает `Error`), а не в уроке.
* Примеры (реальные строки пака):

```
карандаш|6|ка-ран-даш|1,3|vowel|✏️|Возьми ____ и нарисуй домик.|чем рисуют и пишут|карандАш — три А|karandash
Москва|5|Мос-ква|1|vowel|🏛️|____ — столица России.|главный город||moskva
```

Полный перечень проверок — `scripts/check-content.mjs` (он же запускается
в CI). Ниже правила по полям.

### 4.2. Ударение (`stress`)

* Индекс **ударной буквы в слове** (0-based), не номер слога и не номер гласной.
* Обязано стоять на гласной (`аеёиоуыэюя`), исключений нет.
* **Ударная гласная никогда не отмечается «опасной»** (иначе подчёркнута
  «не та» буква). Единственное исключение — «ё» (см. §4.4).
* Ударение дублируется в `tests/stress-snapshot.ts`: при добавлении каждого
  нового слова строка для снимка обязательна (§4.12).

### 4.3. Слоги (`syllables`)

* Через дефис (`ли-си-ца`), складываются в слово ровно (проверка без пробелов).
* Деление — по школьным правилам переноса; строгая проверка — что строки
  совпадают с текстом, не более того (деление глазами проверяет вычитка).

### 4.4. «Опасные» буквы (`danger`) — сердце методики

Опасными отмечают ровно две категории:

| Категория | Правило | Обязательность |
|---|---|---|
| Безударные **о / е / я / э** | слышатся не так, как пишутся (о→а, е/я/э→и) | **всегда помечаются** |
| Безударные **а / и** | «словарная» орфограмма 2 класса (на слух = о/е) | разрешены, помечаются как словарные («карандаш», «малина», «работа», «улица») |
| Безударные **у / ы / ю** | не редуцируются | **никогда не помечаются** |
| Ударная гласная | не орфограмма | никогда (кроме «ё») |
| **ё** | сама по себе орфограмма («чёрный», а не «чорный») | помечается, даже если ударная |
| Сомнительные согласные (звонкость/глухость: «завод», «мороз») | на конце и перед шумным — не слышатся | помечаются |
| Удвоенные («класс», «суббота», «килограмм») | вторая буква — орфограмма | обе входят в `danger`, как в паке |
| Непроизносимые («праздник», «чувство», «здравствуйте») | буква не слышится, но пишется | помечаются |

Дополнительные правила (все автоматические, `check-content.mjs`):

* красная (опасная) буква не может быть ударной, кроме «ё»;
* если тип `vowel` — все опасные индексы обязаны указывать на гласные;
  `consonant` — на согласные; `other` — и на те, и на другие одновременно
  (например «Россия»: гласные + удвоенная С; «Здравствуйте»: гласная + В).
  Тип, не совпадающий с отмеченными буквами, — ошибка;
* каждое словарное слово обязано иметь **хотя бы одну** опасную букву;
* безударные о/е/я/э, не отмеченные опасными, — ошибка; безударные у/ы/ю,
  отмеченные опасными, — ошибка.

### 4.5. Предложение (`sentence`)

* Ровно **один** пропуск `____`; само слово в предложении встречаться не должно
  (проверка — вхождение подстроки без пробелов, без учёта регистра).
* **Словарная форма.** В пропуск подставляется начальная форма слова, поэтому
  предложение не может требовать другого падежа: «Папа работает на ____» —
  ошибка («на завод» вместо «на заводе»); правильно: «Наш ____ выпускает
  машины».
* Автоматические стражи (все — в `check-content.mjs`, нет смысла дублировать
  логику руками, но надо знать): после предлога пропуск допустим только если
  подстановка совпадает (`магазин` → «в магазин», `метро` → «на метро»,
  `стакан` → «в стакан» — исключения `PREPOSITION_OK`); после слов типа
  «много/мало/кусок/…» нужен родительный (`GENITIVE_HEAD`); после местоимений
  винительного ж. р. («свою», «мою»…) нужна форма на -у/-ю или «ь»; после
  императива на -и нужна винительная форма; перед прилагательным в в. п. ж. р.
  (-ую/-юю) существительное обязано кончаться на -у/-ю/«ь» и т. д.
  Слова с непроверяемой формой — `NO_DECLENSION` (этикетные формулы, «метро»,
  «пальто»). Пограничные случаи «синим / открой» — предупреждения
  (`ADJ_CASE_REVIEW`), решаются вычиткой, а не молчанием.
* Ответ не должен быть угадываем по смыслу («птица» как подсказка к пяти
  разным птицам — ошибка по §4.7).

### 4.6. Подсказка (`hint`)

* Обязательна у каждого слова, длина ≥ 4 символа.
* Должна **называть именно это слово**, а не категорию: «чем рисуют и пишут»
  — да; «птица» или «как?» — нет. В заданиях «напиши слово» без нормальной
  подсказки ребёнок не может начать.
* Для служебных и отвлечённых слов — пояснение значения простыми словами
  («как-то раз, в какой-то день» — «однажды»).

### 4.7. Мнемоника (`mnemonic`) — по желанию, но без права врать

Автоматические проверки:

* «две С» / «три О» и т. п. — количество букв в слове должно совпадать
  ровно (словари числительных `NUM_WORDS`: один/одна/одну/два/две/три/
  четыре/пять);
* заглавная буква внутри мнемо-слова = ударение или опасная буква (проверяются
  по индексам); первая заглавная у имени собственного разрешена;
* «мягкий знак на конце» — слово обязано кончаться на «ь»;
* мнемоника должна давать ребёнку реальный способ запомнить написание,
  а не пересказ определения.

### 4.8. Эмодзи (`emoji`)

* Обязательны (плита-эмодзи показывается, когда нет картинки; эмодзи — также
  часть компактных мест интерфейса). Один эмодзи на слово, без составных
  последовательностей, не читаемых на старых Android.
* Эмодзи не должен подсказывать опасное место (это написание, а не смысл)
  и не должен повторяться у десятков слов одной темы — тогда образ перестаёт
  различать (это было мотивом массовой генерации картинок, см. §7).

### 4.9. Картинка (`image`) — необязательное поле, обязательное покрытие

* Имя файла **без расширения**, слаг: латиница (транслит), цифры, дефис и
  подчёркивание (`/^[a-z0-9_-]+$/`), строчные. Пример: `красная_плошадь` →
  `krasnaya_ploshchad.webp` (пробел → `_`, словосочетания склеиваются
  подчёркиванием).
* Файл обязан существовать: `public/words/<slug>.webp` (проверка в
  `content:check`, отсутствие — ошибка).
* Все слова 1–4 классов покрыты; у 5 класса поле пустое — показываем эмодзи,
  картины рисуем партиями после релиза (§8 плана 5 класса). Правила генерации — §7.

### 4.10. Классы слов и уроки

* Класс слова хранится **не** в строке RAW, а в карте `GRADES_OF`
  (`текст → [классы]`). Старые 94 строки RAW трогать нельзя, поэтому классы
  живут картой — это осознанное архитектурное решение (`classes-1-4.md` §5.1).
* Слово, входящее в несколько словарей, перечисляется во всех них
  (`[3, 4]`) — одна карточка, один прогресс.
* Уроки новых классов строятся функцией `lesson(grade, slug, title, emoji,
  order, words[])`: проверяет, что слова есть в банке и входят в класс
  урока; `id` урока — `g<класс>_<slug>`; порядок `order` — 1..N внутри
  класса. Уроки 2 класса — исторические (`byTheme`, без префикса).
* Тема слова (`theme`) для новых классов вычисляется автоматически как
  `id` первого урока, где слово встречается; поле осталось для обратной
  совместимости и подсказок при вычитке, в логике не участвует.
* В уроке **4–8 слов**; слова из прошлых классов, попавшие в программу
  («обед» в 3 классе), из текущего урока не изымаются — в уроке они стоят
  вместе с новыми, прогресс у них общий.
* Каждое слово класса входит ровно в один урок своего класса — инвариант
  `tests/content.test.ts`.

### 4.11. Хранение класса слова и сборка `LESSONS`

```
RAW (строки) → parse() → WORDS
GRADES_OF    → grades  → id: g2_… (если есть 2 класс) иначе g<min>_…
G1..G4_LESSONS → lesson() → LESSONS → LESSONS_BY_GRADE
AVAILABLE_CLASSES = CLASS_IDS.filter((g) => LESSONS_BY_GRADE[g].length > 0)
```

`CLASS_META` (титульные данные класса, в т. ч. эмодзи и `short`) — единственное
место, где задаётся внешний вид класса в UI.

### 4.12. Снимок ударений и словарь известных ударений

* `tests/stress-snapshot.ts` — снимок «слово → индекс ударной буквы» для
  **всех** слов банка; при добавлении слова строка снимка обязательна,
  иначе `test:content` падает с читаемым «ожидалось …, получено …».
  Лишние записи — тоже ошибка (защита от переименований).
* `tests/stress-dict-snapshot.ts` — снимок словаря `src/content/stress-dict.ts`
  (`KNOWN_STRESS`): ударения для слов **вне банка**, из школьных списков
  («подлежащее» — 6, а не 3-й слог на «е»: ошибка 0.61.0, исправлена 0.61.1).
  Используется `makeCustomWord` для своих слов.
* Ударения школьных слов, которых нет в приложении, в снимок банка не идут.

### 4.13. Импорт нового списка и вычитка взрослого

1. `node scripts/words-from-text.mjs list.txt > words.draft.txt` — черновик:
   слоги расставлены автоматически, ударение/опасные буквы помечены `AUTO`;
   если в исходнике стоят ударения (акутом или апострофом), они считываются.
2. Ручная разметка каждой строки: ударение, опасные буквы, эмодзи, предложение
   (падежи!), подсказка, мнемоника при наличии. Глазами — не по скрипту.
3. `npm run content:check` — зелёный, плюс предупреждения `⚠ К вычитке
   вручную` разобрать каждое.
4. `npm run test:content` — связность классов и уроков.
5. **Вычитка взрослым:** значение, естественность фразы, отсутствие ответа,
   соответствие возрасту; вторая вычитка — **сверка с печатным словариком
   издания 2025/2026** (состав словарей расходится на 1–3 слова).
6. Только после этого — релиз класса.

### 4.14. Типовые ошибки (грабли, на которые уже наступали)

* «на завод» вместо «на заводе» — неверный падеж в пропуске (§4.5);
* «каранДаш с тремя А, но одна С» в мнемонике — мнемоника врёт про количество;
* ударная гласная подчёркнута как «опасная» — подсказка превращается в ошибку;
* безударная «и» помечена опасной «для единообразия» — подсвечивается не та буква;
* подсказка «птица» у пяти птиц — ребёнок угадывает;
* слово видно в собственном предложении — вспоминать нечего;
* «ё» в письме не засчитана — лонг-фикс `sameTypedWord` не применён;
* правка существующих строк RAW «попутно» — ломает проверенные карточки;
* `GRADES_OF` не покрыл RAW или содержит лишний ключ — `test:content` падает
  (проверка покрытия);
* ударение сдвинуто на соседнюю гласную — ловит только снимок (§4.12).

## 5. Карточка слова: правила оформления

Актуальный дизайн — вариант **B «Фотокарточка»** (решение пользователя
2026-10-06, см. `docs/word-cards-design.md`). Карточка — один компонент
`WordCard` для всех мест приложения; не плодить свои вёрстки.

### 5.1. Анатомия (сверху вниз)

```
WordCard
├─ WordArt         — «плита» картинки: рамка 2 px, радиус clamp(16px, size×0.24, 30px),
│                    padding size×0.12 (безопасная зона), тёплая тёплая подложка
│  └─ .word-art    — img (object-fit: contain) ИЛИ эмодзи на той же плите
├─ .wcard-word     — слово с ударением, «опасной» буквой и «окошком» (WordLetters)
└─ .wcard-body     — подпись: слоги, предложение, мнемоника, статистика/кнопки
```

### 5.2. Токены и размеры (в `src/styles/tokens.css` / `app.css`)

| Токен | Значение | Назначение |
|---|---|---|
| `--art-hero` | `clamp(136px, min(46vw, 24dvh), 184px)` | герой-плита в карточке; не больше четверти экрана |
| `--wcard-gap-art` | 20 px | зазор плита → слово (16 px читалось как «одна группа», 20 — как разрыв, но связка «образ ↔ слово» цела) |
| `--wcard-gap-word` | 16 px | слово → подпись |
| `--sp-1…--sp-7` | 4 / 8 / 12 / 16 / 20 / 24 / 32 px | единственная шкала отступов; **магических чисел в новых стилях нет** |
| `--wcard-pad` | 20 px | поля карточки |
| `--art-plate` | `#fffdf7` (тёмная: `#2b2544`) | подложка плиты — не белая, тёплая («паспарту») |
| Миниатюра в словарике | 22 px | высота пилюли задаёт размер |
| Ударная/опасная буква | заглавная акцентным цветом; окошко — рамка | ребёнок видит обе диакритики |

### 5.3. Чип «опасной» буквы

* Поля в долях кегля: `padding: 0 .16em`; радиус `.22em`;
* цвет `--orange-ink`: `#b45309` (светлая) / `#fbbf24` (тёмная);
  контраст к подложке ≈ 4.5 : 1 — буква не «растворяется»;
* запрещается сшивать чип с соседними буквами и с плитой (зазоры обязательны).

### 5.4. Доступность и темы

* Цели нажатия для детей — **от 44 px**, лучше 2×2 см; мелкие элементы
  не «сшивать» визуально (NN/g, Material 3, HIG).
* Минимальная ширина экрана поддержки — **320 px**; карточка не вылезает за
  кадр, прокрутка допустима только внутри подписи.
* **Тёмная тема обязательна** для всех новых элементов: цвет — токеном,
  не зашитым hex; проверять в обеих темах и в пяти оформлениях приложения.
* Контраст текста — не ниже AA для того размера, которым он набран.

### 5.5. Эмодзи-плита

Эмодзи — 0,54 от плиты, с мягкой тенью; плита и рамка те же, что у рисунков.
Ребёнок не видит визуальной разницы между «есть картинка» и «ещё нет»,
кроме смены образа.

### 5.6. Правила для новых стилей

* Только токены (`--sp-*`, `--wcard-*`, `--art-*`); никаких «на глаз 14 px»;
* 8-станция сетка Material/HIG (шаг 4/8);
* ничего не «приклеено к буквам»: любой блок рядом с плитой имеет зазор ≥ 12 px;
* новые композиции карточек — через параметр `?cards=plate|photo|split`
  (превью в `docs/word-cards/`), не правкой единственной разметки.

## 6. Подача учебного материала (методика)

### 6.1. Цикл работы со словом

1. **Знакомство (LOOK–SAY):** слово целиком, ударение, слоги, «опасная»
   буква мигает; картинка или эмодзи-плита.
2. **Орфографическое проговаривание:** читаем по слогам так, как пишется.
3. **Закрепление:** окошко, сборка слова из букв, выбор верного написания.
4. **Извлечение из памяти:** написать слово целиком (в т. ч. зрительный
   диктант — единственная замена слуховому).
5. **Интерливинг:** слова прошлых уроков возвращаются по расписанию.
6. **Отработка ошибки:** правильное написание + мнемоника + слово
   возвращается в урок.
7. **Пауза после ответа — это разбор, а не пустое поле:** отвеченное задание
   остаётся на экране (буквально нельзя нажать, но верно/неверно и свой ответ
   видно); полоса снизу показывает результат, награду и словарное написание
   с подсвеченной опасной буквой; кнопка «Далее ▸». Подробно —
   `docs/answer-feedback.md`.
8. **Подсказка в каждом задании (💡):** 50:50 в окошке, подстановка буквы
   в сборке, контур слова при письме, подглядывание в диктанте, мнемоника/
   опасная буква в остальных. Ответ с подсказкой — **7 XP вместо 10**,
   но остаётся правильным: помощь не наказывается жёстко.

### 6.2. SRS (повторение)

Упрощённый SM-2 (`src/engine/srs.ts`): интервалы растут при верных ответах,
ошибка обнуляет серия и возвращает слово в урок. «Повторение» — единственный
глобальный урок (`REVIEW`, `id: 'review'`): собирается из **всех** изученных
слов, не привязан к классу. Это решение защищает межклассовое повторение
и невыполнимость задания дня при смене класса (`classes-1-4.md` §8).

### 6.3. Уровни уроков и «класс пройден»

* Урок закрыт при **уровне 5** (пять корон на «Моём пути»).
* Класс считается пройденным, когда **все его уроки** достигли уровня 5
  (`classComplete` в `src/engine/classes.ts`) — это «уроки пройдены»,
  а не «все слова освоены»; порог освоенного слова (`s ≥ 90`) — отдельная
  метрика, видна в процентах.
* Главная показывает «N класс пройден! 🎉» и кнопку следующего класса
  (`nextClass` — ближайший доступный класс выше текущего из
  `AVAILABLE_CLASSES`); на экране результата последнего урока — то же самое;
  в «Родителям → Обзор» — таблица всех классов.
* Ничего дополнительного за «класс пройден» не выдаётся (экономика не
  меняется без отдельного решения).

### 6.4. Письмо и «ё» (напоминание для контента и тестов)

«е» вместо «ё» при письме = верно; «учёник» вместо «ученик» = ошибка.
После ответа вердикт всё равно показывает написание с «ё».

### 6.5. Свои списки («к контрольной»)

* `src/content/preset-lists.ts` — готовые пресеты списков к контрольным
  (добавление одной кнопкой; разбор через `parseWordList`).
* `src/content/custom-words.ts` — карточки для слов вне банка (картинка,
  подсказка, предложение, мнемоника); если слова нет и там — автополя +
  честная пометка «проверьте ударение».
* `src/content/stress-dict.ts` — ударения для этих слов (§4.12).
* Правило для контент-PR: новое слово школьного списка → строка в
  `custom-words.ts` + картинка в `public/words/` + при необходимости
  ударение в `stress-dict.ts` (+ снимок `stress-dict-snapshot.ts`).

### 6.6. Возраст и тон

Продукт — для начальной школы (7–11 лет). Отсюда: крупные кнопки, минимум
текста, никаких негативных формулировок и «штрафов»; ошибка — сигнал к
разбору, а не к наказанию. Для 5 класса (11–13 лет) сложность подачи должна
остаться той же: простая лексика в подсказках и предложениях, иначе класс
провалится методически (см. `docs/proposals/slova-5-klass.md`).

## 7. Картинки к словам

### 7.1. Спецификация файла

| Параметр | Значение |
|---|---|
| Формат | WebP, **256×256**, без прозрачности |
| Вес | цель ≈2–6 КБ; предел партии — **20 КБ**; пак слов 1–4 классов (257 файлов) ≈ 1,4 МБ |
| Фон | однотонный тёплый кремовый **`#FAF4E1`** (как у 94 картинок 2 класса) |
| Стиль | плоские иллюстрации, простые геометрические формы, мягкое однотонное затенение, **без обводки**, насыщенная, но спокойная палитра (зелёный/синий/жёлтый/красный/коричневый) |
| Композиция | **один предмет**, по центру, с воздухом по краям (~8–12 % полей), мягкая эллиптическая тень под предметом |
| Текст | **нет букв, цифр, надписей и «ценников» — никогда** (иначе картинка подсказывает написание) |
| Кадр | квадратный, «стикер», 1:1 |
| Метаданные | вычищаются (`-strip`) |

### 7.2. Пайплайн (никогда не руками в `public/`)

```bash
# 1. кадр кладётся в images-src/gen/<slug>.png   (папка вне git, .gitignore)
# 2. проводим в пак:
node scripts/make-word-image.mjs --trim   # кадры → public/words/<slug>.webp
                                          # (--trim — если генератор оставил поля)
# 3. слаг пишем 10-м полем RAW (src/content/words.ts)
# 4. проверки:
npm run content:check                      # файл существует, имя валидно
npm run images:report                      # таблица покрытия по классам
npm run images:report -- --strict          # упадёт, если у класса есть слова без картинки
npm run build && npm run test:boot         # precache в норме
```

Legacy-скрипт `npm run images` (`make-word-images.mjs`, `images-src/*.png`)
оставлен для перерисовки исходных 94 картинок 2 класса.

### 7.3. Партии и приёмка

* **Лимит — 3 кадра за один подход.** Больше не генерируем и не «добиваем
  остаток» в том же ходе: качество проверяется глазами, а не оптом.
* Партия = один заход = максимум 3 кадра → сразу в контент
  (`make-word-image.mjs` → поле RAW → `content:check` → `images:report`).
* Один кадр = один предмет. Отклонения от пака 2 класса (другая палитра,
  обводка, 3D, фото-стиль, мелкие детали) — брак, переделываем.
* **Брак не подключается молча:** слово остаётся с эмодзи — эмодзи-плита
  лучше плохой картинки. Если решение не нашлось — слово остаётся на эмодзи
  и это фиксируется в отчёте о партии.
* Для отвлечённых слов (уровень C: «однажды», «вчера»…) картинка делается
  только сценой; если сцена в 256 px читается хуже эмодзи — оставить эмодзи.

### 7.4. Шаблон промпта (меняется только предмет)

```
Flat vector illustration for a children's spelling app.
Subject: <ПРЕДМЕТ>. Single centered object, no other objects.
Style: flat vector, simple geometric shapes, soft single-tone shading,
no outlines, saturated but calm palette (green, blue, yellow, red, brown),
warm cream background #FAF4E1, soft elliptical shadow under the object.
No text, no letters, no numbers, no watermark, no frame, no border.
Square composition with margins, sticker-like, 1:1.
```

### 7.5. Precache и бюджет офлайна

* `vite.config.ts` (workbox): `globPatterns` включает `**/*.webp`;
  `maximumFileSizeToCacheInBytes: 12 * 1024 * 1024`; тяжёлые и точечные
  ресурсы (base-tours, naash, buk3d, покупная музыка) в precache
  **не входят** — это осознанная экономия офлайна.
* Каждая новая картинка в precache — трафик каждого устройства; +100 карточек
  ≈ +0,5–0,7 МБ. Добавлять партиями и с `images:report` на руках.
* Coverage — цифры, а не мнение: `images:report` печатает таблицу
  «класс / слов / с картинкой / на эмодзи» и вес файлов.

### 7.6. Политика для 5 класса (решение от 2026-11-09)

1. Релиз 5 класса выходит **на эмодзи** (как 3 и 4 класс в 0.28/0.30):
   контент первичен, картинки — улучшение, а не блокер.
2. Покрытие 100 % — отдельными партиями ≤3 кадра после релиза класса;
   цель и бюджет фиксируются в `docs/proposals/slova-5-klass.md` после
   получения списка слов.
3. Приёмка каждой партии — по чек-листу §7.3; после закрытия —
   `images:report -- --strict` зелёный и заметка релиза.
4. Стиль — строгий шаблон §7.4; новых стилей «для 5 класса» не вводим.

### 7.7. Журнал картинок

Единственный источник правды по покрытию и истории партий —
`npm run images:report` и `docs/proposals/word-images-priority.md`
(туда же заносить партии 5 класса после релиза).

## 8. Классы: архитектура и добавление нового класса

### 8.1. Модель данных (в текущей сборке — 1–4 класс)

| Сущность | Где | Правило |
|---|---|---|
| `ClassId` | `src/types.ts` | `1 \| 2 \| 3 \| 4` — union-тип; расширение — добавить литерал |
| `Word.grades` | `src/types.ts`, `GRADES_OF` | классы словарей, в которых встречается слово |
| `Lesson.grade`, `GradeLesson` | `src/types.ts` | урок программы класса; `REVIEW` — вне классов |
| `Profile.activeClass` | `src/types.ts`, `src/state/store.ts` | программа ребёнка; старые сохранения → 2 |
| `isClassId` | `src/state/store.ts` | валидатор на входе и при импорте; неизвестный класс не записывается |
| `availableClass()` | `src/content/words.ts` | ближайший доступный класс для отрисовки; сохранённое значение не перезаписывается |
| `CLASS_META` | `src/content/words.ts` | `{ title, short, emoji }` класса; единственный источник внешнего вида |
| `AVAILABLE_CLASSES` | `src/content/words.ts` | вычисляется по непустым `LESSONS_BY_GRADE`; UI показывает только готовые классы |

Прогресс (`profile.words`, `profile.lessons`) ключуется глобальными
`wordId`/`lessonId` и классу не принадлежит.

### 8.2. Чек-лист добавления класса (по образцу 0.27.0 / 0.28.0 / 0.30.0)

1. **Типы** (`src/types.ts`): расширить `ClassId`. `tsc` покажет все места.
2. **Контент**: строки RAW нового класса — **в конец** блока RAW (как 3 и 4
   класс); `GRADES_OF` — на каждое новое слово и на существующие слова,
   входящие в словарь нового класса (с ними — одна карточка, `grades` растёт);
   `CLASS_IDS`, `CLASS_META`, `G5_LESSONS` (`lesson(5, …)`); экспорты
   `LESSONS_BY_GRADE`, `WORDS_BY_GRADE`. `AVAILABLE_CLASSES` и тема слова
   обновятся сами.
3. **Стор**: `isClassId` — литерал нового класса; дефолт старых профилей
   остаётся 2; `setActiveClass` / `setProfileClass` — без изменений
   (они уже generic по `ClassId`).
4. **UI**: `ClassSheet`, `SettingsTab`, `WordsScreen`, `ProfilesScreen`,
   `OverviewTab`, `HomeScreen`, `LessonScreen` — всё строится от
   `AVAILABLE_CLASSES`; правки точечные: «вся программа 1–4» → «1–5»
   (`LessonScreen.tsx`, компонент `ClassWinMeta`), таблица классов в
   «Родителям → Обзор» появится сама.
5. **Тексты**: `src/platform/share.ts` (`SHARE_TITLE`, `SHARE_TEXT`),
   `index.html` (`<meta name="description">`), `vite.config.ts`
   (`manifest.description`), `package.json` (`description`),
   `README.md` (заголовок, разделы «Классы», «Как заменить список слов»),
   комментарии в `src/content/words.ts`, `src/engine/classes.ts`,
   `src/state/store.ts` (интерфейсные строки «1–4» → «1–5»).
6. **Тесты**:
   * `tests/content.test.ts`: `EXPECTED[5] = 127`, `WORDS.length = 367`;
     сводная строка `console.log`; проверка префикса `g5_` для новых слов;
     `AVAILABLE_CLASSES` → `[1,2,3,4,5]`;
   * `tests/adaptive.test.ts`: добавить `WORDS_BY_GRADE[5].length`;
   * `tests/stress-snapshot.ts` (+ размер) и, при необходимости,
     `tests/stress-dict-snapshot.ts`;
   * `tests/classes.test.ts` + блок в `tests/smoke.test.tsx`: путь нового
     класса, переключение 4→5 и обратно без потери XP/кристаллов, «класс
     пройден» и переход дальше (для 5 класса — «вся программа 1–5»);
   * `scripts/image-coverage.mjs`: `classes = [1,2,3,4,5]`.
7. **Релиз**: версия minor (новый функциональный этап), заметка
   `docs/RELEASE-X.Y.Z.md`, заголовок `vX.Y.Z — 5 класс: …`, полный контур §3.4.

Полный пошаговый план с оценками — [`proposals/slova-5-klass.md`](./proposals/slova-5-klass.md).

### 8.3. Инварианты, которые держат тесты

* `WORDS_BY_GRADE[g].length === EXPECTED[g]` для каждого класса;
* каждое слово класса — ровно в одном уроке своего класса;
* `LESSONS` отсортированы по (класс, `order`), `order` = 1..N;
* `AVAILABLE_CLASSES` = классы с непустыми уроками;
* у слов 2 класса — `g2_`, у слов без 2 класса — `g<min>_`;
* `GRADES_OF` покрывает все строки RAW полностью (без лишних ключей);
* у «обед»/«тарелка»/«грамм»/«килограмм»/«интересно» — одна карточка
  с двумя классами.

### 8.4. Чего новый класс НЕ делает

* Не трогает `THEME_OF` и уроки 2 класса; не перенумеровывает `order`;
  не меняет `id` существующих слов; не сбрасывает прогрессы; не меняет
  экономику и пороги наград; не вводит новые сущности в профиле
  (нового поля `activeClass` достаточно).

## 10. Что нельзя без отдельного решения владельца

Стоп-лист (см. также §2 и `docs/HANDOFF.md`):

* озвучка и любые аудиофайлы слов; транскрипция;
* случайные/платные лутбоксы за слова, изменение экономики за прохождение класса;
* изменение порогов наград (например «Знаток» 25 слов, рост БУКа 12/30/60)
  ради выросшего объёма банка;
* сброс/миграция прогресса детей; принудительное переприсвоение классов;
* правка проверенных строк RAW 1–4 классов «попутно»;
* добавление в пак «жёлтый»/«шёл» (словарик 2 класса) — только отдельным релизом;
* смена стиля картинок (3D, обводка, фото, новая палитра) и шаблона промпта;
* новые сущности в профиле под конкретный класс;
* удаление или переименование `src/content/*` и `GRADES_OF` → обратно в RAW;
* публикация PR с красными CI или без bump версии.

## 11. Словарь терминов

| Термин | Значение |
|---|---|
| RAW | строчный блок контента в `src/content/words.ts` (источник всех карточек) |
| «Опасная» буква | буква, где написание расходится со звучанием (§4.4) |
| Снимок ударений | `tests/stress-snapshot.ts` — замороженные ударения всех слов банка |
| Плита (`WordArt`) | «паспарту» вокруг картинки/эмодзи в карточке слова |
| Слаг (`slug`) | имя файла картинки без расширения (`/^[a-z0-9_-]+$/`) |
| Корона | уровень урока (1–5); 5 = урок закрыт |
| SRS | интервальное повторение (упрощённый SM-2) |
| Интерливинг | подмешивание слов из прошлых уроков в текущий |
| «Класс пройден» | все уроки класса имеют уровень ≥ 5 |
| Эмодзи-плита | карточка слова, где вместо картинки крупный эмодзи (вариант до/без генерации) |
| Precache | офлайн-кэш service worker'а (workbox), заполняемый при установке PWA |
| Класс-фильтр | `profile.activeClass`: какие уроки показывать, а не отдельный пак слов |
| Контент-пак | общее название `src/content/words.ts` и связанных файлов |

## Приложение A. Как добавить одно слово (контент-PR)

1. Слово отсутствует в банке? Проверьте `grep -n '<слово>' src/content/words.ts`.
2. Отрезать строку по формату §4.1 и добавить в **конец** RAW (для 5 класса —
   там же); классу дать `[…, 5]` в `GRADES_OF`.
3. Разметить: ударение, слоги, опасные буквы, `dangerKind`, эмодзи,
   предложение (падеж!), подсказку, мнемонику.
4. Строка снимка в `tests/stress-snapshot.ts` (+ `STRESS_SNAPSHOT_SIZE`).
5. `npm run content:check && npm run test:content` — оба зелёные; рассмотреть
   предупреждения вычитки.
6. (По желанию) картинка — приложение B.
7. Вычитка взрослым → сверка с учебником → релиз по §3.

## Приложение B. Как добавить/заменить картинку

1. Кадр → `images-src/gen/<slug>.png` (вне git).
2. `node scripts/make-word-image.mjs --trim` (или `node scripts/make-word-image.mjs <slug>`).
3. Слаг — 10-м полем RAW; при замене существующей картинки поле не меняется.
4. `npm run content:check && npm run images:report` — покрытие выросло.
5. Глазами: карточка, урок, словарик, экран результата; светлая и тёмная тема; 320 px.
6. `npm run build && npm run test:boot`.
