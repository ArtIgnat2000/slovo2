# 0.114.3 — урок: пустой лоток букв больше не показывается

Скриншот с телефона (2/11, «Правильно!»): после сборки «воробья» под буквами
оставался пустой лоток — большая кремовая плашка с пунктирами, в которой уже
нечего было показывать. Она отнимала высоту у вердикта и кнопки «Далее».

## 1. Что изменилось

`WordTileBoard` рендерит лоток только пока в нём есть **хотя бы одна буква**:

```tsx
{state.tray.length > 0 && (
  <div className="letters tileboard-tray" …>
```

Как только все буквы разобраны — после верной сборки или после ошибки, пока
доска сбрасывается, — лоток исчезает целиком. Лунки со словом остаются на
экране, вердикт и баннер получают освободившееся место. Подпись «Буквы
разобраны» больше не нужна и удалена вместе с пустым контейнером.

Раньше это правило работало только в свободной игре (`unscored && solved`),
а в уроке лоток оставался сознательно — «там он часть задания». Скриншот
показал, что после ответа это уже не задание, а пустая плашка.

## 2. Проверка всех таких случаев

* **Урок «Собери слово»** — исправлено; лоток исчезает после сборки.
* **Свободная игра «Собери слово»** — работало с 0.96.6; теперь то же условие,
  один код на оба режима.
* **Слоговая мозаика** (`SyllableBoard`) — лоток не пустеет: использованные
  слоги остаются в нём приглушёнными, чтобы можно было вернуть ход.
* **Слоговая остановка «Тропы»** (`WordTrailGame`) — то же: плитки остаются
  на месте, показывается пройденный путь.
* **Кроссворд, филворд, колесо, мемори** — отдельных пустых лотков нет.

Других мест, где контейнер оставался бы пустым, аудит не нашёл.

## 3. Правило проекта

В [`PROJECT-RULES.md`](./PROJECT-RULES.md), §2 «Нерушимые правила», добавлен
пункт **11: пустых контейнеров не бывает**. Если лоток, слот, плита или полоса
опустели — элемент уходит из разметки, а не остаётся рамкой на своём месте.
Это относится ко всем новым экранам, не только к `WordTileBoard`.
