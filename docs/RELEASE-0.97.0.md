# 0.97.0 — кроссворд и филворд помещаются на планшете

Замечание владельца (2026-11-12, скриншот iPad в портрете):
«На планшете есть проблемы у кроссворда и филворда. Не помещается на экран
по вертикали. Очень неудобно».

На скриншоте видно главное: решётка кроссворда занимает почти всю высоту
экрана, пул букв идёт третьим рядом, а список вопросов уезжает под нижнее
меню — виден только первый чип. Филворд на том же экране ещё хуже: его поле
растягивалось на всю ширину карточки (клетка по 77 px), и слова-цели тоже
уходили под вкладки.

## Почему не помещалось

С 0.96.0 вкладка «Игры» — «один экран, одна игра»: сцена `.games-stage`
прокручивается, но **внутри** игра всегда была одной колонкой. На телефоне
это правильно (сцену прокручивают), на планшете — нет: по вертикали
складывались четыре блока.

| Блок (iPad 810×1080, кроссворд) | Высота |
|---|---|
| шапка с переключателем игр | 115 px |
| строка состояния («Собрано: …») | 40 px |
| решётка (11 колонок × 9 строк) | 507 px |
| пул букв (3 ряда плиток) | 162 px |
| список вопросов (5–6 чипов) | 309 px |
| **итого** | **~1130 px** при доступных **889 px** |

## Что изменено

1. **Две колонки внутри игры (планшет, ширина ≥ 720 px).** Кроссворд: решётка
   с пулом букв слева, вопросы справа — как в обычном кроссворде. Филворд:
   поле слева, слова-цели справа. На телефоне всё как было: одна колонка,
   порядок «решётка → пул → вопросы» не изменился (зазоры выровнены по
   `var(--sp-2)`, телефон отрендерен пиксель в пиксель как в 0.96.6).
   Порог 720 px, а не 760: iPad mini в портрете — 744 px, он тоже должен
   получать две колонки.
2. **Сцена «Игр» на планшете шире** — 720 px → **1040 px**. Двум колонкам
   нужно место, а правило «сцена не расползается» осталось: на десктопе
   экран по-прежнему не шире 1040 px.
3. **Поле филворда получило потолок ширины** (`--ws-cell`): раньше оно
   занимало всю карточку (на iPad клетка выходила 77 px). Теперь клетка
   52 px на планшете, 40–46 px на телефоне.
4. **Клетка обоих полей получила потолок по высоте окна**
   (`src/ui/useBoardCellCap.ts` → `--cw-cell-cap` / `--ws-cell-cap`). Считаем
   от реального места: окно минус шапка сцены и нижнее меню, минус строка
   состояния, поля карточки и пул букв под полем. Клетка не мельче 32 px
   (палец ребёнка), но решётка больше не выпирает за экран.

## Что стало

| Экран | Было | Стало |
|---|---|---|
| iPad 810×1080, кроссворд | карточка 1082 px, вопросы **под меню** | карточка 801 px, **всё на экране** |
| iPad 810×1080, филворд | поле 658×658 (клетка 77 px), цели **под меню** | поле 458×458 (клетка 52 px), цели справа |
| iPad 1080×810 (альбом) | вопросы под меню | карточка 609 px в сцене 619 px — влезает |
| iPad mini 744×1133 | одна колонка | две колонки, всё на экране |
| телефон 390×844 | — | без изменений (пиксель в пиксель) |

Замеры сделаны в headless Chromium на собранной сцене (810×1080 и другие
размеры), до и после правки.

## Проверки

`npm run typecheck`, `npm run test:smoke`, `npm run build`, `npm run test:boot`,
`npm run release:check`.

Новые проверки в `tests/games-ui.test.tsx` (`runGamesTabletLayoutChecks`):
- на планшете кроссворд разложен в две колонки (`grid-template-areas`:
  `grid words` / `tiles words`), филворд — в две (`grid-template-columns`);
- на телефоне игра осталась в одну колонку;
- клетка кроссворда на планшете — `min(48px, var(--cw-cell-cap, …))`,
  филворда — `min(52px, var(--ws-cell-cap, …))`;
- у поля филворда есть потолок ширины (иначе оно снова растянется на карточку);
- сцена на планшете шире 720 px.

Живой UI: у кроссворда и филворда появилось тело игры (`.cw-body` / `.ws-body`)
с доской и боком — тесты проверяют, что вопросы и пул лежат внутри тела, а
потолок клетки реально проставлен (`--cw-cell-cap` в `style` решётки).

## Правило

«Две колонки» в «Играх» — это **две колонки внутри одной игры**, а не две
игры рядом: на экране всегда одна механика (0.96.0). Проверяется стражем в
`tests/games-ui.test.tsx` — раскладка уже откатывалась один раз (0.94.1).
