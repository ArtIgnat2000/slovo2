## Зафиксированные решения по тюнингу

- **Аксессуары:** только уже купленные вещи; по четыре цвета на вещь (база плюс три оттенка). База бесплатная. Открытие нового оттенка стоит 1 💎; переключение между открытыми, повторный выбор и возврат к базе бесплатны. Платное открытие подтверждается диалогом; баланс не уходит в минус. Палитра доступна вне урока; кружки имеют подписи и зону касания не меньше 44 px.
- **Костюмы:** менять можно только акцент собранного костюма — свечение и плащ, если он есть. Корпус, живот, крылья и металл не перекрашивать: это часть идентичности заработанного костюма. У несобранного костюма кнопки нет; его тюнинг нормализация удаляет. Экономика та же, что у аксессуаров.
- Тюнинг сохраняется в профиле/выгрузке. Неизвестные id, дубликаты и настройки некупленных вещей или несобранных костюмов отбрасываются; старые профили без новых полей читаются как базовый вид. Снятие вещи, смена костюма и перенос профиля не должны терять уже открытые оттенки.
- Базовые цвета аксессуаров должны совпадать с историческими цветами; исходные `glow` и `cape` костюмов берутся из самих костюмов. Регрессионные проверки не должны допускать незаметного изменения прежнего вида.

## Что нельзя добавлять без отдельного согласования

- Родительский ПИН; озвучку и аудиофайлы; бросок БУКа с инерцией; подглядывание во время урока; реакции вне урока; резерв места на экране результатов; checkpoint; свободный числовой слайдер; жизни/сердечки; стресс-таймеры; публичные лидерборды.
- Узоры и принты (например, полоски, звёзды, клетка) как вторую ось тюнинга; перекраску корпуса костюмов; аватар/фон профиля; наборы красок со скидкой; случайные или сезонные цвета; перекраску некупленных вещей.
- Не вводить случайные/платные лутбоксы, плату за базовый цвет, повторную оплату уже открытого цвета, платный возврат к базе, дневные лимиты на краски, апгрейды характеристик под видом тюнинга или изменение `wardrobeValue` из-за красок.

## Контур проверок

Полный локальный контур перед PR (`release:check` сравнивает с актуальным
`origin/main`):

```sh
npm run test:release
git fetch origin main && PR_TITLE="vX.Y.Z — …" npm run release:check -- origin/main
npm run typecheck
npm run content:check
npm run test:content
npm run test:adaptive
npm run test:smoke
npm run audit:storage
npm run build
npm run test:boot
```

CI (`.github/workflows/check.yml`) гоняет тот же набор и дополнительно:
`audio:check`, `server:test`, `test:galleries`, `test:guard`, `test:icons`,
`test:contrast`. При изменениях музыки — `npm run audio:check`; при
изменениях макета магазина — `npm run demo:check`; при картинках —
`npm run images:report [-- --strict]`. Отдельно вне контура: `npm run test:qr`
(нужны `npm i --no-save qrcode jsqr`).

Ориентиры на 2026-11-12 (последний прогон на `main` = 0.97.1): контент —
367 карточек (30/94/72/94/127) и 257 картинок; смоук — все проверки
зелёные; `audit:storage` — 10 сценариев без безвозвратной потери прогресса;
`test:boot` — пустого экрана нет. `npm run pickup` при старте сессии
прогоняет typecheck, content, adaptive, storage audit, smoke и boot.

**Зелёный контур ≠ готово.** Он не заменяет вычитку контента и живую
проверку на телефоне: узкий экран 320–360 px, ландшафт, тёмная тема,
попадание пальцем.

## Известные грабли

- **Очередь сторожа хранилища (урок 0.21.2).** Все операции `GuardedStorage`
  (чтения, записи, удаления) идут через общую очередь `enqueue` — чтение в
  обход очереди обгоняет висящую запись и возвращает устаревший снимок
  (так «пропадала» купленная музыка). Внутри задачи очереди, работающей с
  основным ключом (`restoreSnapshot`), нельзя вызывать `set()` состояния
  профиля: persist поставит в очередь полную запись ПРЕЖНЕЙ памяти, и она
  ляжет после сырого восстановления — `rehydrate` прочитает затёртое.
  Порядок: сырые операции с ключом — в очереди; `set()` меток сейфа — после
  `unfreeze()` + `rehydrate()`. Регрессии: смоук «покупка музыки переживает
  немедленную повторную синхронизацию…», `audit:storage` сценарий 10.
- **Базовое `.mascot` — `position: fixed` в правом нижнем углу** (плавающий
  БУК). Каждый контейнер, где сова является картинкой, ОБЯЗАН снимать
  позицию (`position: static; z-index: auto; animation: none`); без сброса
  плитка выглядит пустой (урок 0.21.2: строки «Мои костюмы»). Сбросы есть у
  `.shop-wear-icon`, `.wishlist-card-art`, `.shop-collect`, `.puzzle-win`
  (+ `.puzzle-win .mascot.dance` возвращает танец — правило с равной
  специфичностью позже базового `.mascot.dance` глушило анимацию),
  `.shop-icon`, `.shop-mascot`, `.shop-hero-art`, `.shop-bigart(-toy)`,
  `.tech-buk`, `.hangar-buk` (0.22.0 — `inset: auto`, `z-index: 1`: БУК над
  ковриком сцены), `.chest-ceremony-buk`, `.buk-owl`, `ShopDemo .mz-*`.
  Новый контейнер с совой — добавь сброс и страж в `tests/puzzles-ui.test.tsx`.
- **`equipped.toy` с 0.22.0 — «любимая вещь на главном подиуме ангара»**,
  а не «надето на БУКе». Не возвращать `MascotToy`/`<image>` внутрь SVG
  маскота: техника экспонируется только в `HangarScene` (решение
  пользователя, §7 `docs/proposals/large-items-scene.md`). Стражи: смоук
  «купленная техника не рисуется на БУКе» (нет `<image>` в маскоте),
  `shop-tuning` (`showsOnBuk` — false для всей техники), CSS-правило
  `.hangar-buk .mascot` в `puzzles-ui`.
- У `.mascot` был глобальный `z-index: 25`, из-за чего замок несобранного костюма оказывался под совой. В релизе у иконок магазина и масок надетого костюма `z-index: auto`, у замка — `z-index: 1` и тень; при изменениях слоёв проверять это наложение.
- Для zustand 5 / `useSyncExternalStore` пустое значение тюнинга должно быть стабильной константой, а не новым объектом на каждом чтении/рендере.
- При SSR-превью промо надо задавать профиль через начальное состояние Zustand: `renderToString` читает серверный snapshot. Для листов есть `scripts/promo/make_accents.mjs` и `scripts/promo/accent-cards.tsx`; запускать с `OUT_DIR=docs/promo/<дата>`, для `resvg` нужен флаг `--promo`.
- `tsconfig.tsbuildinfo` — генерируемый кэш: он исключён из Git и после `build` не должен попадать в `git status`.
- Смена `src/engine/tints.ts` или палитр не должна менять базовый внешний вид. Проверять реальные базовые цвета в тестах, а не только данные палитры.
- Данные тюнинга входят в профиль и выгрузку. Любая нормализация/миграция должна сохранять оплаченные открытия и не повреждать старый прогресс; перед изменениями состояния учитывать `npm run audit:storage` и защитные тесты импорта.
- Bump только в `package.json` ломает `release:check` (случай 0.15.0 → сервисный 0.15.1): версия должна совпадать в `package.json`, `package-lock.json:version` и `package-lock.json:packages[""]`; перед слиянием гонять `npm run release:check` локально.
- **У `.cw-grid` обязателен `width: 100%` вместе с `max-width`:** без него
  grid с колонками `1fr` схлопывается в точки (урок 0.96.4, кроссворд
  «не собирался»). Страж — в `tests/crossword.test.tsx`.
- **Круг слов в играх живёт на устройстве, а не в компоненте** (урок 0.97.1):
  курсор и слова прошлой сетки лежат в `localStorage` под ключом
  `slovo2-game-cursor` (`ws:<класс>` для филворда, `cw` для кроссворда).
  Любая пересборка экрана (`key` по длине пула, возврат на вкладку, смена
  профиля) обнуляла курсор в состоянии, и сетки начинали круг заново.
  Приоритет трудных слов должен переупорядочивать саму колоду (`poolDeck`),
  а не поднимать слова поверх окна — иначе они висят в первой сетке каждый раз.
- **`.game-clue` — подсказка-строка свободной игры** (иконка 64 px + текст),
  осознанное исключение из правила «картинка сверху»: под Android колонка
  занимала ~214 px и экран не помещался (0.96.6). Правило для карточек слова
  и подсказок урока (`.clue*`, `.wcard*`) не тронуто, страж в `lesson-art-ui`
  смотрит только мимо `.game-clue`.
- Вычисленный CSS-цвет — не пиксели на экране: Samsung Internet может перекрасить страницу, не меняя `getComputedStyle` (урок диагностики 0.14.4/0.14.5). Не заявлять живую проверку темы без реального устройства.
