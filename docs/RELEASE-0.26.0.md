# Релиз 0.26.0 — проверка обновлений вручную

## Что изменилось

**«Родителям» → «Приложение»: кнопка «Проверить обновления».** Приложение и
раньше проверяло новую сборку при запуске и показывало плашку «Доступно
обновление», но установленный на телефон ярлык может неделями не закрываться —
родитель оставался на старой версии и не понимал, почему на сайте другой номер.
Теперь в карточке «Версия» можно спросить браузер вручную.

Проверка заново запрашивает `sw.js` через `registration.update()` и, если файл
изменился, ждёт установки нового сервис-воркера (до 20 секунд). Ответы честные
и не подменяют друг друга:

* **последняя версия** — новой сборки нет;
* **есть новая версия** — рядом кнопка «Обновить сейчас»; прогресс, покупки и
  профили сохраняются, страница перезагружается уже на новой сборке;
* **нет интернета** — проверить можно позже, занятия работают и офлайн;
* **проверить нельзя** — страница открыта без сервис-воркера (например,
  `npm run dev`); это не выдаётся за «версия последняя»;
* **ошибка** — сеть пропала, сервер не ответил, таймаут или сорвавшаяся
  установка.

Перезагрузка после «Обновить» теперь ждётся по нативному `controllerchange`, а
не только по событию workbox: так плашка и ручная проверка работают одинаково,
даже если событие `waiting` пришло не туда. Логика — `src/platform/pwa.ts`
(`checkForUpdate`, `applyUpdate`), экран — `src/ui/parent/UpdateCheck.tsx`.

## Проверки

`tests/update-check-ui.test.tsx` (входит в `npm run test:smoke`) проверяет
кнопку, повторную доступность после ответа, ожидающего и докачивающегося
воркера, отсутствие обновления, таймаут, ошибку сети, офлайн-ответ без запросов
и то, что «Есть новая версия» с кнопкой «Обновить сейчас» появляется только при
найденном обновлении.

Проверены также `typecheck`, `test:adaptive`, `test:release`, `release:check`,
`content:check`, `audio:check`, `build`, `test:boot`, `demo:check`.
