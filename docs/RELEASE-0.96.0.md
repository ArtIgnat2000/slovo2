# 0.96.0 — «Игры»: один экран, одна игра, всё помещается

Переработка интерфейса игрового раздела по замечанию владельца: «есть
проблемы с интерфейсом на телефоне и планшете — не помещается и неудобно».
Скриншот (iPhone, вкладка «Игры») показал три причины сразу:

1. **Три игры лежали друг под другом.** Вкладка была «простынёй»: на телефоне
   экран заканчивался лотком с буквами, а филворд и кроссворд находились
   сильно ниже — ребёнок про них просто не знал.
2. **Плитки с буквами не влезали.** Лунки и лоток были флекс-строкой с
   фиксированными 46–62 px, поэтому слово из 10–17 букв переносилось «как
   получится» и уезжало под нижнее меню (на скриншоте видно обрезанный
   второй ряд «й с»).
3. **Подсказка и список слов съедали высоту.** Картинка брала до 220 px,
   а 60 чипов-слов раздували карточку ещё на 130–170 px.

## Что изменено

- **Один экран — одна игра.** Сверху сегмент-переключатель
  «🧵 Собери слово · 🔎 Филворд · ✏️ Кроссворд» (роль `tablist`, `aria-selected`),
  ниже — ровно одна игра и одна строка описания «что тут делать». Раньше все
  три механики показывались одновременно.
- **Экран держит высоту окна.** Шапка и переключатель фиксированы, игровое
  поле занимает остаток и прокручивается только оно (`.games-stage`). Высота
  берётся из флекса `.app` (`min-height: 100dvh`), поэтому баннеры обновления
  и установки ничего не выдавливают, а низ экрана резервирует 76 px под
  нижнее меню.
- **Доска с плитками раскладывается по длине слова** (`boardColumns` в
  `ui/WordTileBoard.tsx`): ≤ 7 букв — один ряд, 8–17 — 4–7 колонок с полным
  последним рядом (нет «сирот» из одной буквы). Плитка делит ширину карточки,
  высота выводится через `aspect-ratio`, потолок 62 px, пол на тесном экране
  держит прокрутка, а не сжатие буквы.
- **Убранная буква оставляет пустое место** (`.tileboard-gap`): оставшиеся
  плитки не перескакивают с места на место после каждого тапа — ребёнок не
  «теряет» плитку из-под пальца. В уроке «дырка» держит прежние 44×52 px.
- **Слово выбирается лентой вбок** (одна строка, горизонтальная прокрутка,
  `scroll-snap`), а не «стеной» из 60 чипов на пол-экрана.
- **После сборки — «Другое слово →»** в баннере победы: свободная игра ведёт
  слово за словом. Экран больше не переключает слово сам (похвалу ребёнок
  должен успеть увидеть).
- **Подсказка в игре компактнее**: картинка 88–152 px (в уроке — до 192 px)
  через токен `--art-clue`; на коротком экране (≤ 700 px по высоте) — 96 px,
  на ≤ 560 px скрывается подпись-объяснение.
- **Плавающий БУК не летает в «Играх»** (`App.tsx`): на скриншоте сова висела
  в правом нижнем углу ровно поверх лотка с буквами и перехватывала касания.
- **Филворд и кроссворд** получили те же компактные правила: инструкция одной
  строкой, «победа» — плашкой в одну строку, на телефоне меньше зазоры клеток,
  на планшете сцена не расползается на всю ширину (max-width 720 px).
- **Планшет (≥ 760 px):** та же одноколоночная сцена вместо двух колонок
  (0.94.1): на экране одна игра, а слишком широкое поле филворда и кроссворда
  читалось хуже.

## Почему так, а не «ещё плотнее»

Плотность добрана сменой композиции, а не уменьшением целей: у детей 7–9 лет
палец крупнее, Material и Apple требуют цель ≥ 48 pt, поэтому плитки и
клетки остаются пальцевыми, а из экрана убраны абзацы, «стена» чипов и
вторая игра. Контраст текста на переключателе проверен во всех 16 темах
(в neon чернила активного пункта берутся из `--neon-primary-ink`).

## Проверки

`npm run typecheck`, `npm run test:smoke` (новые блоки: сегмент игр, одна
игра на экране, прокручиваемая сцена, лента чипов, `--slot-cols` на доске,
раскладка 8–17 букв без «сирот», «дырка» от убранной буквы, «Другое слово»),
`npm run test:contrast` (16 тем, 288 пар), `npm run build`, `npm run test:boot`.

## Что НЕ трогали

- Механики, движки (`word-board`, `word-search`, `crossword`), награды,
  SRS/XP — без изменений: «Игры» по-прежнему ничего не считают.
- Контент слов и картинки — без изменений.
