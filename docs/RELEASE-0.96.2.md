# 0.96.2 — «Филворд»: разные слова, а не один жёсткий набор

Замечание владельца: «в филворд добавь, чтобы были разные слова, а не жёстко
только один набор. Смена сетки меняет и слова». Так и было: движок брал слова
строго по убыванию длины, поэтому каждое поле состояло из одних и тех же
самых длинных слов изученного пула — «извините», «карандаш», «обезьяна»,
«дежурный» выпадали из сетки в сетку, а короткие слова класса не появлялись
никогда.

## Что изменено

- **Слова выбираются случайно.** Порядок в списке у движка — это приоритет
  («что легло, то и спрятано»), поэтому теперь список перемешивается, а не
  сортируется по длине. Якорь (первое слово, его заметнее всего искать)
  каждый раз новый — случайное из самых длинных свежих слов.
- **Разные длины на одном поле.** После якоря идут остальные слова пула
  вперемешку: раньше в сетку попадали только 8-буквенные, теперь рядом
  встречаются «апрель», «метро», «вдруг» и «карандаш».
- **«Новая сетка» / «Ещё сетку» меняет и слова.** Экран передаёт движку
  `avoidIds` — слова прошлой сетки; они уходят в конец очереди. На пуле
  «Игр» (до 60 слов) новая сетка не повторяет ни одного слова из прошлой;
  на очень маленьком пуле (класс только начат) слова возвращаются — пустой
  экран хуже повтора. Порог честный: если свежих слов меньше семи, движок
  не отсекает прошлые вовсе.
- **4–7 слов на поле** (`WORDS_TARGET = 5`, предел `WS_MAX_WORDS = 7`):
  сетка перестала быть то «двухсловной», то перегруженной.
- Детерминизм сохранён: один `seed` и один пул дают одну и ту же доску —
  на этом стоят смоук-тесты.

## Что НЕ трогали

- Геометрия поля (8×8 / 9×9, рост до 12×12), правила линий и диагоналей,
  подсветка «опасных» букв, отсутствие XP/SRS — без изменений.
- Контент слов — без изменений.

## Проверки

`npm run typecheck`, `npm run test:smoke`, `npm run build`, `npm run test:boot`.
Новые проверки: разные seed дают разные наборы; «новая сетка» на большом пуле
не повторяет слова прошлой; на крошечном пуле доска всё равно собирается;
UI — «Ещё сетку» меняет именно слова, а не только их места.

## Дальше

- Прогон с ребёнком: не выпадают ли из поля самые нужные слова слишком
  надолго (круговорот идёт по всему пулу класса, а не по «слабым» словам).
- Возможная следующая итерация: приоритет словам, у которых больше ошибок
  (`profile.words[id].wrong`), — сейчас выбор равномерный.
