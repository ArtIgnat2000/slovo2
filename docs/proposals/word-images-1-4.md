# Картинки к словам 1–4 классов: решение 0.31.0

**Дата:** 2026-10-22 · **Состояние:** 0.31.0 · **Статус:** решение принято,
рисование вынесено в отдельные партии.

## 1. Что есть сейчас

| Класс | Слов | С картинкой | На эмодзи |
|---|---:|---:|---:|
| 1 | 30 | 28 | 2 («лисица», «мальчик») |
| 2 | 94 | 94 | 0 |
| 3 | 72 | 1 («обед») | 71 |
| 4 | 94 | 1 («тарелка») | 93 |
| **Всего** | **257** | **94 (37%)** | **163** |

Цифры печатает `npm run images:report` (`scripts/image-coverage.mjs`) —
это единственный источник правды: он читает `RAW`, `GRADES_OF` и реально
существующие файлы `public/words/*.webp`.

94 иллюстрации 2 класса — плоские рисунки в палитре приложения, WebP 256×256,
≈5–6 КБ каждая, все в precache service worker'а. Слова без картинки уже
показывают эмодзи на той же «плите» (`WordArt`, класс `.word-art-frame.no-image`),
поэтому пустых рамок в интерфейсе нет.

## 2. Варианты

| Вариант | Что делаем | Плюсы | Минусы |
|---|---|---|---|
| **A. Оставить эмодзи** | Ничего не рисуем; доводим эмодзи-карточку | 0 КБ, 0 работы, офлайн уже работает | образ беднее рисунка; эмодзи зависит от шрифта устройства |
| **B. Нарисовать все 163** | Партиями по 20–30, как делали 2 класс | единый стиль у всей программы; сильнее визуальная память | ≈2–4 недели работы с вычиткой; +0,8–1,0 МБ precache |
| **C. Гибрид (очередями)** | Сначала самые частые/трудные слова 3–4 класса, остальное — эмодзи | эффект там, где ошибок больше; можно останавливаться | покрытие неполное; нужен список приоритетов |
| **D. Сгенерировать пакетно нейросетью** | Прогнать промпты и отобрать кадры | быстро | стиль поплывёт; нужна ручная вычитка каждого кадра (всё равно ≈B по времени), риск «подсказки» в рисунке |

## 3. Решение

**Принят вариант C: гибрид, очередями.** В 0.31.0 картинки не рисуем —
вместо этого:

1. **Эмодзи-карточка доведена до аккуратного вида.** Эмодзи крупнее
   (0,54 от плиты) и с мягкой тенью; плита и рамка те же, что у рисунков.
   Ребёнок не видит «недоделанную» карточку.
2. **Покрытие измеряется, а не обсуждается.** `npm run images:report`
   печатает таблицу по классам и вес файлов; с `--strict` падает, если
   у класса остались слова без картинки (пригодится, когда решим закрыть
   100%).
3. **Порядок следующих партий** (когда появится время на рисование):
   * 3 класс — 71 слово: сначала уроки «Погода и природа», «Огород»,
     «Транспорт» (там больше всего ошибок по отчёту родителя);
   * 4 класс — 93 слова: сначала «Вокзал и дорога», «Профессии»,
     «Деревня»;
   * 1 класс — 2 слова («лисица», «мальчик») как быстрый финиш.

   Партия = один PR: исходники в `images-src/` (не коммитятся),
   `npm run images`, имена — в 10-е поле `RAW`, `npm run content:check`,
   `npm run images:report`, `build`. Проверка приёмки: каждый файл
   ≤ 8 КБ, 256×256, без текста и без подсказки написания.

## 4. Почему не рисуем всё сразу

* Контент важнее: 163 карточки — это ~2–4 недели вычитки, а программа
  1–4 классов уже работает.
* Precache: +163 файла ≈ +0,9 МБ на каждое устройство. Сейчас сборка
  8 МБ, запас есть, но каждая партия должна оставаться в рамках
  `maximumFileSizeToCacheInBytes` и здравого смысла офлайн-PWA.
* Эмодзи уже даёт образ; рисунок — улучшение, а не блокер.
