## 2. Правила работы

1. **Лимит — 3 кадра за один подход.** Больше не генерируем и не «добиваем
   остаток» в том же ходе: качество проверяется глазами, а не оптом.
2. **Партия = один подход = максимум 3 кадра.** После партии кадры сразу
   проводятся в контент: `images-src/gen/<slug>.png` → `public/words/<slug>.webp`
   (`node scripts/make-word-image.mjs`) → 10-е поле `RAW` → `npm run content:check`
   → `npm run images:report`.
3. **Порядок не переставляем без причины.** Сначала то, что даёт ребёнку
   максимум (см. §3), в конце — отвлечённые слова, где картинка может скорее
   запутать, чем помочь.
4. **Один кадр = один предмет.** Без текста, букв, цифр и ценников: это
   словарный тренажёр, картинка не имеет права подсказывать написание.
5. **Стиль единый** (шаблон промпта — §5). Отклонения от пака 2 класса
   (другая палитра, обводка, 3D) — брак, переделываем.
6. **Брак не удаляем молча.** Если кадр не подошёл, слаг остаётся в этой
   таблице со статусом `↻`, а в контент не попадает: эмодзи-плита лучше
   плохой картинки.

## 3. Как составлен приоритет

Три уровня, сверху вниз:

* **A. Эмодзи не различает слова.** 55 слов, где один и тот же эмодзи стоит
  у 2–7 разных слов: `📅` у шести дней недели и календаря, `🌾` у пшеницы,
  овса, соломы, агронома и сеялки, `🏖️` у берега, песка и каникул, `⚖️` у
  грамма и килограмма, `🌿` у петрушки и сирени. Здесь картинка не «украшает»,
  а **впервые начинает что-то значить** — это первый сорт.
* **B. Конкретный предмет с уникальным эмодзи.** Рисунок заменяет хороший
  знак: выигрыш меньше, но образ становится частью серии пака.
* **C. Отвлечённое и служебное.** `однажды`, `потом`, `вокруг`, `интересно`,
  `приветливо`, `свобода`, `богатство`. Рисовать можно только сценой, а сцена
  в 256 px читается хуже эмодзи; делать в последнюю очередь и с особым
  контролем (если не получилось — оставить эмодзи).

Внутри уровня порядок — **по урокам**, чтобы после партии выглядел
законченным не случайный набор, а целая тема «Погода и природа», «Огород»,
«Вокзал и дорога».

## 5. Промпт и стиль

Шаблон (постоянная часть — обязательна, меняется только предмет):

```
Flat vector illustration for a children's spelling app.
Subject: <ПРЕДМЕТ>. Single centered object, no other objects.
Style: flat vector, simple geometric shapes, soft single-tone shading,
no outlines, saturated but calm palette (green, blue, yellow, red, brown),
warm cream background #FAF4E1, soft elliptical shadow under the object.
No text, no letters, no numbers, no watermark, no frame, no border.
Square composition with margins, sticker-like, 1:1.
```

Почему так: 94 картинки 2 класса — плоские, без обводки, на кремовом фоне
`#FAF4E1`, с мягкой тенью-эллипсом и полями ~8 %. Шаблон повторяет эти
признаки, иначе партия выпадет из серии.

## 6. Приёмка одной партии

- [ ] в кадре ровно один предмет, он целиком влез и стоит по центру;
- [ ] **нет букв, цифр, надписей и «ценников»** — иначе картинка подсказывает
      написание и партия не принимается;
- [ ] палитра и фон как у пака 2 класса (никакой 3D, обводки, фото);
- [ ] `node scripts/make-word-image.mjs` дал WebP 256×256, ≤ 20 КБ;
- [ ] слаг вписан в 10-е поле `RAW`, `npm run content:check` зелёный;
- [ ] `npm run images:report` показывает рост покрытия нужного класса;
- [ ] `npm run build` + `npm run test:boot` — precache не больше 12 МБ на файл;
- [ ] глазами на 320 px: «словарик», урок, экран результатов, светлая и
      тёмная тема (картинка на кремовом фоне не должна «резать» тёмную тему);
- [ ] для отвлечённых слов (уровень C): если кадр читается хуже эмодзи —
      не подключаем, пишем в отчёт «оставлено эмодзи».

иконки видны на каждом экране и меняют ощущение приложения сильнее, чем

Наблюдения по ходу:

* Кадры выходят ~1250 px, после `--trim` в паке 3–6 КБ — запас по весу
  большой (предел 20 КБ на файл, пак вырос на 36 КБ при 9 картинках).
* Генератор рисует фон не ровно `#FAF4E1`, а чуть темнее/светлее; в паке это
  незаметно, потому что фон всё равно перекрывается при `-extent`. Если
  появится серия кадров «в рамке» — переходить на прозрачный фон нельзя:
  у 94 картинок 2 класса его нет, серия развалится.
* **Обрезка краёв опасна**: при `-resize 256x256^` фигура мальчика обрезалась
  по грудь. Скрипт вписывает кадр целиком (0.92 от стороны) — проверяйте
  крайние кадры (высокие фигуры, длинные предметы) глазами.
* Часы на башне, цифры на кубиках, буквы на вывесках — самая частая причина
  брака. В промпте «no numbers» помогает не всегда: смотреть каждый кадр.
* **Кадры овощей (партии 4–5):** вышли «в серию» даже без
  отдельной подгонки — фон, тени и палитра совпали с паком 2 класса, так что
  переделывать принятые кадры не пришлось ни разу. Брак пока только один класс
  ошибок — лишние цифры/буквы, и он ловится на просмотре.
* **Повторный проход по «сложным» знакам оправдан:** там, где эмодзи был один
  на несколько слов (петрушка/сирень, ромашка/одуванчик), кадры пришлось
  разводить по форме, а не по оттенку — иначе в списке слов получались
  близнецы. Это единственная категория, где я перегенерировал бы кадр даже при
  формальном соответствии промпту.
* **Лимит за ход — 10 генераций, а не 3.** Правило «3 кадра за партию» —
  про приёмку и проводку в контент, а не про потолок инструмента. В этом ходе
  вышло 10 кадров (6 партий по 3 и 1) — это верхняя граница, дальше только
  следующим ходом. Если ход начинается с плана «10 кадров», порядок волн
  не меняется: последняя партия может остаться неполной (`goroh` без
  `petrushka`/`oreh`).
