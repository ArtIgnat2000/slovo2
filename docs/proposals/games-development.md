**Коротко про пункт 3.** Играть бесплатно и «доступ за успехи» можно совместить
без наказания ребёнка: **одна игра всегда открыта**, остальные открываются
по ключам за текущий день (уроки, задания дня, баллы — всё уже считается).
Замки мягкие: игра открывается на день, ранее открытые не отнимаются,
доступна любая из открытых на выбор, а не «именно эта». Подробно — §8.

**Что делать первым.** 0.98.0 «Чувство победы» (1–2 дня): сейчас победа в
филворде и кроссворде — статичная плашка без звука, конфетти и честной
строки о наградах. Это самый дешёвый и самый заметный шаг, и именно его
стоит проверить руками на телефоне, прежде чем переделывать витрину (§11).

## 0. Коротко: что предлагаю делать

1. **Не тащить комплект целиком.** Он написан во многом «с нуля» и в 14
   местах расходится с правилами проекта: шрифты Google (офлайн-PWA),
   палитра мимо токенов, озвучка, таймеры, жизни, «проигрыш»,
   лутбокс-мотивация (подробно §2). Из 15 механик проходят фильтр 4–5.
2. **Первый релиз — «Чувство победы» (0.98.0).** Самая дешёвая и заметная
   доработка: сейчас победа в филворде и кроссворде — статичная зелёная
   плашка, без `sfx.finish`, без конфетти (компонент уже есть в проекте) и
   без `gameAwardHint` (написан, но не показан нигде). 1–2 дня — и именно
   этот шаг надо проверить руками на телефоне первым.
3. **Второй — витрина + доступ (0.99.0).** Вкладка упирается в три кнопки
   в один сегмент (§4), а игры открываются за успехи дня (§8). Оба
   изменения переделывают один экран, поэтому делаются вместе: две группы
   по времени + шкала ключей + мягкие замки с подписью «Откроется за урок».
   3–4 дня.
4. **Дальше — механики по одной, с «Мемори» впереди** (§6-B). В 5 классе
   она честно работает текстом («слово ↔ значение»), картинки не нужны —
   это ответ владельца, и он снимает главный риск игры.
5. **Материала не хватает не на механики, а на контент.** Фраз в банке
   всего 4 (§6-D), 5 класс без картинок. Поэтому «Собери фразу» отложена
   до контент-релиза, а расширение сеток для 5 класса (§6-G) — отдельным
   поздним релизом, чтобы не трогать три работающих движка в одном релизе
   с переделкой витрины.
6. **Экономику не трогаем.** Игры уже дают ограниченный XP с потолком
   (`GAME_XP_CAP = 6`, 1 💎 за сетку), SRS не меняется. Никаких наклеек,
   валют и «Коллекции слов» — её работу делает кольцо прогресса в словаре
   (§9). Вместо неё — рекорды и счётчик сеток на `localStorage`.

**Чего в плане нет и не будет:** БУК в играх (§7 — отклонено владельцем),
замки ради замков (доступ всегда оставляет одну игру открытой, §8.3),
таймеры, жизни, лутбоксы, новая валюта, миграция профиля.

## 2. Сверка комплекта с правилами проекта

Это ядро документа: что из присланного берём, что переписываем, что

**Главный вывод §2:** комплект — хороший чек-лист ожиданий от детской игры

Поэтому дальше — только то, что согласуется с §2 `PROJECT-RULES.md`.

## 3. Принципы «Игр» СЛОВО (выведены из проекта, не из комплекта)

1. **Играть можно всегда.** Ничего не сгорает, и как минимум одна игра
   открыта в любой момент — даже если сегодня не было ни урока, ни задания
   (решение владельца 2026-11-12, §8.3). Доступ расширяется за успехи дня,
   но никогда не сужается и не отнимает уже открытое. Ошибка не наказывает
   и не «портит» слово в SRS.
2. **Игра — не второй кран наград.** Малый XP с потолком, кристалл за первую
   сетку, половинный вес в заданиях дня. Урок остаётся главным.
3. **Слова — из банка.** Никаких «слов из воздуха»: игра тренирует то, что
   ребёнок встретит в уроках (или уже встретил).
4. **Один экран — одна игра** (0.96.0). Новая игра обязана поместиться на
   Android 360×640 вместе с нижним меню.
5. **Офлайн и вес.** Ни одного нового сетевого запроса, ни одной новой
   библиотеки без доказанной нужды. Ассеты — только WebP из `public/`.
6. **Тема-независимость.** Только `var(--*)` и `color-mix`; контраст —
   `npm run test:contrast`.
7. **Ребёнок не должен уметь проиграть.** Нет таймеров, нет жизней, нет
   «попыток кончились».
8. **Ошибка — мягкая:** «Хмм… попробуй ещё», подсветка цвета, не красный крест.

## 4. Проблема №1, о которой комплект молчит: куда девать новые игры в UI

Сейчас выбор игры — сегмент из трёх кнопок
(`.games-switch`, высота 44 px, подписи 12,5 px), и тест
`tests/games-ui.test.tsx` жёстко ждёт **ровно три** кнопки. Четвёртая и
пятая игра в этом сегменте на 360 px дадут три строки текста в 40 px высоты.

Варианты (по правилу №8):

| Вариант | Как выглядит | Плюсы | Минусы |
|---|---|---|---|
| **A. Сегмент с горизонтальной прокруткой** | те же кнопки, лента вбок | минимум кода, привычно | на телефоне две игры «за кадром» — не найдут; тест переписывать |
| **B. Два уровня: «быстрые» + «сетки»** | сегмент 2 группы (🃏/🔎), внутри — выбор игры карточками | игры группируются по настроению (5 минут / 10 минут) | лишний тап, сложнее объяснить |
| **C. Хаб-сетка карточек игр (2×3) вместо сегмента** | на экране сетка миниатюр: эмодзи, название, «1 из 5» | видно всё, растёт до 6–8 игр, каждая карточка ≥ 64 px | «один экран — одна игра» → лишний экран перед игрой; ломает привычку 0.96.0 |
| **D. Сегмент «Собери · Найди · Реши» + свайп** | три группы-таба, внутри свайп между играми | сохраняет текущую полосу | свайп-навигация для 7 лет — плохо открывается без подсказки |

**Решение владельца (2026-11-12): вариант B — начинаем с двух групп.**

Что это значит в деталях, чтобы не было «лишнего тапа»:

* Верхняя полоса остаётся **в одну строку**, но кнопок становится 2 вместо 3
  — на 360 px это заведомо читаемо.
* **Группы по времени, а не по жанру** (ребёнку понятнее):
  * **«Быстро»** (1–2 минуты, 1 сетка) — «Собери слово», «Колесо букв»,
    «Хитрая буква»;
  * **«Подумать»** (3–5 минут) — «Филворд», «Кроссворд», «Мемори»,
    «Слоговая мозаика».
* Внутри группы — **карточки игр 2×2** (эмодзи + название + размер сетки).
  Тап по карточке сразу запускает игру: отдельного «экрана игры» нет,
  так что «лишнего тапа» по сравнению с сегментом не появляется.
* **Состояние по умолчанию:** вкладка запоминает последнюю группу и
  последнюю игру в сессии (`useState`, как сейчас `'build'`), но при
  холодном старте открывает **«Быстро»** с уже открытой игрой — чтобы
  ребёнок сразу мог играть.
* **Совместимость с доступом (§8):** замок живёт на карточке игры;
  группы не скрываются целиком, даже если в группе пока всё закрыто
  (иначе ребёнок не поймёт, что там что-то есть). Пустая группа показывает
  строку «Откроется за урок».
* **Тесты:** `tests/games-ui.test.tsx` ждёт ровно 3 `.games-switch-btn` —
  при B их будет 2, тест переписывается вместе с вёрсткой (это ожидаемо,
  не «сломалось»).

*Если игр станет 6+ — переходим к варианту C (хаб-сетка без групп).*
Решение нужно до первой новой игры, потому что от него зависит вся
вёрстка вкладки.

## 6. Предложения по механикам

Каждая: суть → какие данные нужны → чему учит → стоимость → риск → фаза.
Оценки — в «днях работы» по меркам этого проекта (включая тесты и правку
документов, без учёта ревью).

### A. «Чувство победы» — визуальный и звуковой финал игр — **P0, 1–2 дня**

* **Суть:** общий мини-слой «финал игры» для всех механик:
  * верное слово/пара → `sfx.correct()`, `haptic.correct()`, `glow` на объекте
    (0.5 с, `box-shadow` от `--green`), короткий `pop`-масштаб;
  * победа сетки → `sfx.finish(3)` + `Confetti` (переиспользовать
    `ui/Bits.tsx`, 20–24 частицы) + `haptic.finish()`;
  * в кроссворде — звук на каждое собранное слово (`slotStatus: good`).
* **Данные:** нет. Только существующие `sfx`, `haptic`, `Confetti`.
* **Учит:** ничему (это рамка) — но делает повторяемую игру «событием».
* **Стоимость:** 1–2 дня. Основное время — тесты (`games-ui.test.tsx`
  проверяет состав экрана побед) и проверка `prefers-reduced-motion`.
* **Риск:** низкий. Единственное ограничение — не больше 3–4 анимаций сразу:
  конфетти на победе гасит `glow` на чипах.
* **Как делаем (уточнено при реализации 0.98.0):** не добавляем новые
  анимации, а переиспользуем то, что уже проверено в уроке:
  `sfx.finish(3)` + `haptic.finish()` + `Confetti` (24 частицы, из
  `ui/Bits.tsx`) на победе, `sfx.correct()` из выбранного набора «Звуков»
  на каждое верное слово в кроссворде. При `prefers-reduced-motion`
  конфетти не показываем (`ui/motion.ts` → `prefersReducedMotion()`),
  звук и вибрация остаются. `gameAwardHint()` выводим строкой в плашке
  победы рядом с наградой — там, куда смотрит ребёнок.
* **Фаза:** 1 — **первый релиз после согласования, 0.98.0** (решение
  владельца 2026-11-12).

### B. «Мемори» — найди пару — **P0, 3–4 дня**

* **Суть:** классика: карточки рубашкой вверх, ищем пары. Флип — `rotateY`
  на карточке ≤ 80 px, при `reduced-motion` — fade+scale.
* **Ключевое решение по данным:** пары **слово ↔ картинка** (257 картинок,
  слаги уникальны — коллизий нет), а **не** эмодзи ↔ слово: 70 групп
  совпадающих эмодзи сделают игру нечестной (📅 у восьми дней недели).
* **Режимы (автоматически, по данным):**
  * 1–4 класс: 6–8 пар «картинка ↔ слово»;
  * **5 класс — только текст** (решение владельца 2026-11-12: «пока без
    картинок, если возможно»). Пары «слово ↔ значение (`hint`)», 6 пар.
    Картинок для 5 класса нет и не будет до отдельного контент-релиза,
    поэтому режим не «временный костыль», а полноценный:
    карточка-значение — крупный текст 15–16 px, тап-переворот тот же.
    Проверено: `hint` уникален внутри класса в 1–4 (0 повторов), в 5 классе
    3 повтора — при сборке колоды берём только слова с уникальным `hint`;
    если уникальных меньше 6, добираем парами «слово ↔ число букв» (третья
    строка ниже) или «слово ↔ эмодзи» при отсутствии коллизий эмодзи.
    *Ничего рисовать не нужно: у 5 класса уже есть `hint` у всех слов.*
  * вариант «трудная буква ↔ слово» (по `danger`): карточка показывает
    «безударная О», вторая — слово.
* **Учит:** узнавание слова по образу + орфограмма на виду.
* **Стоимость:** 3–4 дня. `engine/memory.ts` (чистая логика: раскладка,
  выбор пар, ходы), `ui/MemoryGame.tsx`, ~5 проверок в смоуке.
* **Риск:** средний. Главный — **не превратить игру в «угадай картинку»**:
  в 5 классе нужен честный текстовый режим, иначе карточка «помидор» будет
  единственной понятной. Второй — 8 карточек по 72 px на 360 px влезают,
  12 — уже нет: жёсткий кап 6–8 пар.
* **Фаза:** 3 — релиз **0.101.0** (текстовый режим 5 класса согласован
  владельцем 2026-11-12).

### C. «Колесо букв» — проведи по слову — **P1, 2–3 дня** (из `mekhaniki-bukv.md`, вариант E)

* **Суть:** буквы слова по кругу; ребёнок ведёт пальцем по порядку, сектор
  подсвечивается; полное кольцо — «Слово собрано!». Тап работает как
  деградация (доступность, клавиатура).
* **Данные:** `text`, без картинок и эмодзи — работает в любом классе.
* **Учит:** последовательность букв, «телесный» вход в слово; для 1 класса
  (30 слов, ≤ 8 букв) — идеально.
* **Стоимость:** 2–3 дня. `engine/ring.ts` (углы/секторы), `ui/LetterRingGame.tsx`.
* **Риск:** низкий. Не учит письму — подаём как разминку, не как замену уроку.
* **Фаза:** 2 — релиз **0.102.0** (вместе с «Хитрой буквой»).

### D. «Собери фразу» — **отложить** (вопрос владельца, 2026-11-12)

**Что это такое простыми словами.** В банке слов есть не только отдельные
слова, но и фразы из двух-трёх слов. Их **всего четыре на весь банк**
(проверено по `src/content/words.ts`):

| Фраза | Класс |
|---|---|
| `до свидания` | 2 |
| `Красная площадь` | 3 |
| `Московский Кремль` | 3 |
| `Великая Отечественная война` | 5 |

Сейчас они лежат мёртвым грузом: кроссворд (`crossword.ts:329`) и филворд
(`word-search.ts:178`) прямо выбрасывают слова с пробелом, «Собери слово»
работает с буквами одного слова. В 5 классе такая фраза **одна**.

**Что даёт игра.** Ребёнок собирает фразу из карточек-слов в правильном
порядке (перетаскиванием/тапом). Учит не «слово → перевод», а **порядок
слов и целые выражения** — то, что реально нужно в 5 классе, где словарь
становится «многословным».

**Почему я рекомендую отложить, а не делать в первой волне.**

1. **Материала почти нет.** Для 5 класса — одна фраза. Даже если собирать
   фразы из отдельных слов банка на лету (`Красная` + `площадь`), это
   десятки комбинаций, но проверять их правильность нечем: подсказок и
   пояснений у пары слов нет, а придумывать «правильные» сочетания в коде —
   значит учить ребёнка ошибкам. Играть в 4 фразы больше двух раз
   невозможно: ребёнок запомнит ответы.
2. **Движок почти не экономит.** «Общий движок» с «Собери слово» —
   иллюзия: там буквы одного слова, тут упорядочивание N карточек с
   проверкой порядка. Переиспользуется отрисовка карточки, не логика.
3. **Есть игры с большей отдачей на тот же день работы** — филворд,
   кроссворд, мемори на уже существующем банке слов (≈120–130 слов на
   класс, см. §1).

**Когда вернуться.** Как только в банке появится ≥30 фраз на класс
(это отдельная задача по контенту, не по коду) — игра делается за 1–2 дня
и сразу становится осмысленной. Форму игры за это время не меняем, чтобы
не пришлось объяснять ребёнку две версии.

**Что делать сейчас с 4 фразами.** Ничего не ломаем: они остаются в банке
и доступны в словаре (`word-lists`), просто не играются. Это не баг —
это задел.

### E. «Хитрая буква» — детская замена Wordle и виселицы — **P1, 2–3 дня**

* **Суть:** слово банка показано с закрытой «опасной» буквой (`danger`).
  Ребёнок выбирает букву из 4 вариантов; при ошибке — не наказание, а
  **подсказка-ступень**: эмодзи-контекст → значение (`hint`) → мнемоника
  (если есть) → «покажем букву». Три ступени, потом слово открывается
  и засчитывается как «с подсказкой» (без наград сверх обычного).
  Никаких «6 попыток и проигрыш».
* **Данные:** `danger`, `hint`, `mnemonic` — всё есть у 367 карточек;
  мнемоника — у 34 (13/19/2/0/0), значит ступень с мнемоникой опциональна.
* **Учит:** прямо орфограмму — то, ради чего проект существует.
* **Стоимость:** 2–3 дня (переиспользует `Fix` из `TaskView` и `HintBits`).
* **Риск:** средний: «ещё одна подача того же задания». Спасает рамка —
  это свободная игра с флипом карточки, а не урок.
* **Фаза:** 2 — релиз **0.102.0** (вместе с «Колесом букв»).

### F. «Слоговая мозаика» (вместо «Word Cookies») — **P2, 3–4 дня**

* **Суть:** слово разрезано по слогам (`syllables` есть у всех 367 карточек),
  слоги перемешаны и лежат плитками; ребёнок выкладывает слово. Отличие от
  «Собери слово» — единица не буква, а слог: тренирует слоговое чтение и
  перенос, а слова длиной 17 букв становятся доступны.
* **Данные:** `syllables`. Работает во всех классах, включая 5-й.
* **Учит:** слоговая структура, перенос, чтение длинных слов.
* **Стоимость:** 3–4 дня (новый движок `engine/syllable-board.ts` поверх
  `word-board`, слоги-плитки шире — своя сетка).
* **Риск:** средний: в 1–2 классе слоги — часть урока (`Syllables` в
  `TaskView`), нужна проверка, что игра не дублирует задание один в один.
* **Фаза:** 3 — позже, после 0.103.0.

### G. «Сетки по правилам класса» — расширение филворда и кроссворда — **P2, 2 дня**

* Поднять потолок длины слова в кроссворде с 9 (в 5 классе 30 слов ≥ 10 букв
  не попадают в игру), диагонали — с 5 класса во все (сейчас `grade >= 5`).
* Малым классам — наоборот, поле поменьше (6×6 для 1 класса, как и просили
  в решении владельца 2026-11-09, п. 6).
* **Риск:** средний — трогаем работающие движки (`word-search.ts`,
  `crossword.ts`) и их тесты. Делать отдельным релизом, не «попутно».
* **Решение владельца (2026-11-12): отдельным релизом.** В общем цикле
  движки не трогаем; сетки — самостоятельный поздний PR (**0.103.0**) со
  своими тестами. Причины, с которыми владелец согласился:
  1. любая правка `word-search.ts`/`crossword.ts` задевает три работающие
     игры сразу — это самый дорогой по риску участок;
  2. витрина (§4) и доступ (§8) и так переделывают вкладку; смешивать это
     с правкой генераторов сеток — плохо для отладки;
  3. длинные слова 5 класса частично решаются уже сейчас: они есть в
     «Собери слово» и в мемори, где длина не ограничена.
* **Что входит в 0.103.0:** потолок длины в кроссворде, диагонали по классам,
  малое поле для 1–2 класса, прогон `tests/crossword`/`tests/word-search` и
  проверка на всех пяти классах. Ни одного изменения в этом же PR из
  остальной очереди игр.

## 8. Доступ к играм: схема за уроки, задания дня и ⚡ (2026-11-12)

**Ответ владельца:** «игры давать за успехи в выполнении уроков, за
выполнение задания дня; в зависимости от набранных баллов выдавать доступ
на текущий день на одни или несколько игр».

Ниже схема, которая это делает честно и без поломки существующих правил.

### 8.1. Три источника «ключей» — всё уже считается

Новой валюты и новых полей профиля **не нужно**. Все три показателя уже
лежат в `DayStat` и в настройках, ключи считаются из них на лету:

| Источник | Что именно | Где уже есть | Сколько даёт |
|---|---|---|---|
| **Урок** | завершённый урок дня | `DayStat.lessons` (`store.ts:1196`) | **+1 ключ**, засчитываются не больше 2 уроков |
| **Задание дня** | закрытое задание из `planOf(profile)` | `questProgress`, `DayMetrics` (`quests.ts:229`) | **+1 ключ** за каждое (в дне их 3) |
| **Баллы дня** | ⚡ за день | `DayStat.xp`, порог — половина `settings.dailyGoal` (по умолчанию 120 → 60) | **+1 ключ**, один раз за день |

Два важных ограничения, которые делают схему честной:

* **баллы не засчитываются дважды.** Ключ за урок даёт сам факт урока,
  а ⚡-ключ — отдельный, высокий порог (60 ⚡ ≈ полтора урока).
  Поэтому «прошёл один урок» = 1 ключ, а не 2;
* **⚡ из игр в ключи не идут, и это надо вычесть явно.** `DayStat.xp`
  включает награды игр (`store.ts:1249` — `xp: d.xp + award.xp`), поэтому
  считаем `day.xp - (day.games?.xp ?? 0)`. Потолок игр — 6 ⚡ в день
  (`GAME_XP_CAP`), так что эффект маленький, но без вычитания схема
  обходила бы себя же: играть → получать доступ к играм.

### 8.2. Шкала: сколько игр открыто сегодня

| Ключей | Открыто игр | Как это набрать (типичный день) |
|---|---|---|
| **0** | **1** — базовая «Собери слово» | только открыл приложение — уже можно играть |
| **1** | 2 | один урок · или одно задание дня, если урок уже был вчерашним |
| **2** | 3 | два урока · или урок + задание дня · или урок + 60 ⚡ |
| **3** | **4 (все)** | два урока + одно задание · или урок + два задания · или два урока + 60 ⚡ |
| 4+ | 4 (все) | «на сегодня всё открыто» |

Почему такие числа:

* **один урок = одна новая игра.** Ребёнок видит прямую связь «позанимался →
  открылось», без арифметики;
* **полное открытие за 3 ключа** (решение владельца 2026-11-12) — это один
  нормальный день (2 урока или урок + пара заданий), а не «выполни всё до
  последнего»;
* **дальше шкала не растёт** — иначе появляется стимул гриндить задания
  ради ещё одной игры, а это уже работа, не игра;
* пороги вынесены в константы (`KEYS_FOR_GAMES = [0, 1, 2, 3]`), так что
  «мягче/жёстче» — это правка одного массива, а не переделка схемы.

Формула целиком (для `engine/game-access.ts`):

```ts
// Ключи дня: уроки (≤2) + закрытые задания дня + 1 за баллы.
// Баллы уроков и заданий, без наград игр: day.xp уже включает их (store.ts:1249).
const xpFromWork = Math.max(0, day.xp - (day.games?.xp ?? 0));
const keys =
  Math.min(day.lessons, 2) +
  closedQuests +
  (xpFromWork >= Math.max(30, Math.round(settings.dailyGoal / 2)) ? 1 : 0);
const openCount = GAME_KEYS.filter((need) => need <= keys).length + 1; // 1..4
```

### 8.3. Правила, которые нельзя нарушать (границы схемы)

1. **Одна игра доступна всегда.** Базовая не отнимается никогда —
   иначе ребёнок, который не смог пройти урок, не может и играть.
2. **Только сегодня.** Ключи обнуляются с календарным днём (`dayKey()`).
   Ничего не «сгорает» задним числом: вчерашние ключи не отнимались, они
   просто были вчерашними.
3. **Открытая игра не закрывается.** Дошёл до 3 ключей, потом день
   переключился — то, что открыто сейчас, играется до конца сессии.
4. **Выбор свободный.** Ребёнок выбирает **любую** из открытых игр, а не
   «выданную». Никакого «сегодня тебе только филворд».
5. **Ошибки и подсказки ключи не отнимают.** Нет обратного хода: ключ
   только прибавляется.
6. **Награды не меняются.** Внутри игры действуют прежние потолки
   (`GAME_XP_CAP = 6`, 1 💎 за сетку, вес 0.5 в заданиях дня). Доступ —
   это про «когда», а не про «сколько дадут».
7. **SRS не трогаем.** Даже недоступная игра ничего не «портит» слову.
8. **Честная видимость.** Замок показывает условие **заранее**:
   «Откроется за 2 урока» / «Ещё 30 ⚡» — а не «нельзя» без причины.
9. **Взрослый может выключить.** Настройка `settings.gamesGates`
   (`open` — всё открыто, как сейчас; `points` — по шкале) в
   «Родителям → Занятия». По умолчанию — `points` после согласования
   схемы, и это единственное новое поле настроек (не профиля).

### 8.4. Как это выглядит для ребёнка

```
🧩 Игры                    [ Быстро · Подумать ]        ← две группы (§4-B)
┌──────────────────────────────────────────────────────────┐
│ Открыто 3 игры · ещё 1 за урок                           │  ← шкала
└──────────────────────────────────────────────────────────┘
┌───────────────┐ ┌───────────────┐
│ 🧵 Собери слово│ │ 🔎 Филворд     │                        ← группа «Подумать»
│ 6 слов         │ │ 7 слов         │
└───────────────┘ └───────────────┘
┌───────────────┐ ┌───────────────┐
│ ✏️ Кроссворд   │ │ 🔒 Мемори      │
│ открыто        │ │ за 2 урока     │
└───────────────┘ └───────────────┘
```

* Замок — не серая кнопка без объяснений, а карточка с замком и **одной**
  строкой условия («за 2 урока», «за 60 ⚡»); тап по ней показывает то же
  условие крупнее и не ругается. Цвет — нейтральный токен, не красный.
* Внутри открытой игры всё как сейчас: поле, «Новая сетка», счётчики.
* После урока на экране результатов — строка «🎁 +1 игра на сегодня»
  (это и есть «путь ребёнка» из комплекта, только награда реальная).
* Когда открыто всё — строка шкалы превращается в «Сегодня открыто всё»,
  замков на экране нет вовсе.
* Пример реального дня: пришёл → 1 игра; прошёл урок → «+1 игра, открыто 2»;
  закрыл задание дня → 3; прошёл второй урок → все 4. Дальше шкала стоит.
* Если день пустой (0 ключей) — видна только базовая игра и одна строка
  «Сделай урок — откроются новые игры». Никаких упрёков и таймеров.

## 9. «Коллекция слов» и рекорды — пояснение и рекомендация

### 9.1. Что это было в моём предложении (простыми словами)

Комплект предлагал «альбом стикеров»: за успехи ребёнок получает
картинки-наклейки и складывает их в альбом. Я предложил заменить наклейки
на **«Коллекцию слов»** — витрину слов, которые ребёнок уже освоил.

Как это выглядело бы: отдельный экран, где выложены плитки слов его класса;
слово, которое он уверенно знает (или встречал в играх), — цветное, с
эмодзи и подписью; остальные — серые силуэты. Ничего не даёт, ничего не
открывает: просто «смотри, сколько я уже знаю».

**Важно: это не новая игра и не новая валюта.** Это экран-итог.

### 9.2. Почему я рекомендую **не делать** «Коллекцию» отдельным экраном

1. **Она уже есть.** Во вкладке «Слова» лежит словарик класса, и у каждого
   слова есть кольцо прогресса (`srs`-уровень). «Коллекция» — это тот же
   словарик, только другим способом нарисованный. Два экрана про одно и
   то же — прямой конфликт с правилом «чистота интерфейса»
   (`docs/proposals/ui-cleanliness.md`), на который я сам же и ссылался.
2. **Она дублирует смысл.** Ребёнок уже видит рост: кольцо заполняется,
   полоса урока растёт, ⚡ дня копится. Третий индикатор того же самого
   ничего не добавляет, зато добавляет экран, который надо поддерживать.
3. **Стоимость не нулевая.** Новый экран = навигация, состояния пустоты
   («ещё ничего нет»), правила «что считать освоенным» (а это спор о
   `MASTERED_SCORE`, который владелец просил не трогать), адаптив, тесты.
   Дни, за которые лучше сделать филворд.

### 9.3. Что рекомендую вместо этого (и это дешевле)

| Идея | Что даёт | Стоимость | Вердикт |
|---|---|---|---|
| **Рекорды игр** — одна строка «Лучшая сетка: 7 слов» в плашке победы и в «Родителям → Прогресс» | память о результате, которой сейчас **нет вообще** | 0.5 дня, `localStorage`-ключ как `game-cursor`, без полей профиля и миграции | **делать** |
| **Счётчик игр за всё время** — «Ты собрал 24 сетки» мелким шрифтом внизу витрины игр | ощущение накопления без нового экрана | те же данные, что у рекордов | **делать вместе с рекордами** |
| Коллекция-витрина слов | дублирует словарик | 2–3 дня + поддержка | **не делать** |
| Альбом наклеек/стикеров | новая экономика, лутбокс-риск | много | **не делать** (стоп-лист) |

**Итог по §9:** рекорды и счётчик сеток — да (маленькая честная память),
отдельная «Коллекция слов» — нет, потому что её работу уже делает кольцо
прогресса в словарике.

## 10. Дизайн-слой: что конкретно добавляем

Только то, что не ломает 8 стилей и офлайн.

**Почему такой порядок (решение владельца 2026-11-12).**

1. **«Чувство победы» идёт первым — 0.98.0 (сделано).** Это 1–2 дня, не зависит от

   Заодно после 0.98.0 уже видно, как ребёнок реагирует на финал игры.
3. **Рекорды (0.100.0) до «Мемори»** — полдня работы и «память результата»,
   которой нет вовсе; заодно обкатывают `localStorage`-ключ без миграции.
4. **«Собери фразу» — не в этом цикле** (§6-D): в банке 4 фразы, для

5. **Сетки по классам (0.103.0) — отдельный поздний релиз** (решение

   работающие игры, её нельзя делать «попутно».
6. **БУК (§7) из плана убран совсем** — «пока не надо».

**Что уже решено по схеме доступа (§8.6):** 3 ключа = 4 игры (урок → +1
игра), порог ⚡ — половина `dailyGoal`, базовая игра — «Собери слово».
Эти три значения — константы, дальше не обсуждаются, пока не появится
живой опыт на телефоне.

## 13. Риски и что проверять после каждого шага

| Риск | Как страхуемся |
|---|---|
| Пятая игра ломает вёрстку 360×640 | группировка §4-B (2 группы, карточки 2×2); тест «экран помещается»; живой прогон Android |
| Новые цвета ломают темы | только `var()`/`color-mix`; `npm run test:contrast` в CI |
| Конфетти + glow + звук = «много» | ≤ 24 частиц, ≤ 3 анимаций, `prefers-reduced-motion` |
| Награды игр «печатают» кристаллы | `tests/game-awards.test.ts` не трогаем; новые игры вызывают тот же `playGame(words)` |
| Мемори на эмодзи даёт неоднозначные пары | пары только по картинке (уникальные слаги) или по `hint`; фильтр коллизий в движке + тест |
| Новые поля профиля ломают сохранения | сначала `localStorage` (как курсор 0.97.1), `audit:storage` зелёный |
| Тест «ровно три кнопки игр» | переписывается вместе с §4-B (будет 2 группы), не «молча» |
| Замки §8 обижают ребёнка | всегда открыта одна игра; замок с условием, не «нельзя»; тест на «openCount ≥ 1 при нулевом дне»; настройка `gamesGates: open` у родителя |
| Шкала доступа рассинхронизируется с днём | ключи считаются из `profile.days[dayKey()]` и `planOf(profile, dayKey())`, не хранятся; тест на смену даты (полночь) и на план, зафиксированный в `daily.plan` |
| Схема обходит себя (игра → доступ к играм) | ключ за баллы считается по `xp - games.xp`; тест: `playGame()` не увеличивает `openCount` |
| Офлайн | никаких `@import`, CDN, аудиофайлов; `build` + `test:boot` |

**Контур перед каждым PR:** `test:release`, `release:check` с `PR_TITLE`,
`typecheck`, `content:check`, `test:content`, `test:adaptive`, `test:smoke`,
`audit:storage`, `build`, `test:boot` (+ `test:contrast` при стилях).
