# Серверная часть, классные соревнования и аналитика — план и варианты

**Дата:** 2026-10-21 · **Статус:** предложение к обсуждению, не реализовано
**Повод:** запрос пользователя — «видеть результаты коллег по программе и
соревноваться; не хуже, чем в Учи.ру; соревнования внутри класса, школы;
разработчикам — сколько пользователей и обезличенные данные о работе;
серверная часть; поднять Docker на Synology или недорогое облако».

Документ опирается на код этой ветки: офлайн-PWA, профили в IndexedDB,
94 слова и 16 уроков, `engine/` без React, GitHub Pages, версия 0.26.0.
Все числа, оценки сроков и цены — на 2026-10-21, их нужно перепроверять
перед закупкой. Референс-сервер и его тесты лежат в [`server/`](../../server/README.md),
его контракт проверен `npm run server:test` (12 тестов).

## 0. Резюме для решения

**Что предлагается.** Разделить систему на три независимые плоскости и не
смешивать их:

| Плоскость | Где живёт | Что уходит на сервер | Кому нужно |
|---|---|---|---|
| **Учёба** | телефон, IndexedDB — как сейчас | ничего | ребёнок |
| **Социум** | класс/школа на сервере | псевдоним, аватар, производные баллы | ребёнок, учитель |
| **Телеметрия** | сервер, анонимно | install_id и события без имён | разработчик |

Главное правило: **обучение остаётся локальным и офлайновым**. Сервер не
становится источником истины для прогресса, не блокирует урок и не нужен
для занятия. Если сервер упал, приложение работает ровно как сегодня.

**Рекомендация по инфраструктуре — двумя шагами:**

1. **Пилот (1–2 класса, 2–4 недели):** ваш Synology, DSM 7.2+,
   Container Manager, один контейнер API и файл SQLite. Стоимость ≈ 0 ₽
   плюс электричество и домен. Наружу — через DSM Reverse Proxy или
   Cloudflare Tunnel, порт 8080 в интернет не открывать.
2. **Прод (школы, 1 000+ детей):** российский VPS 2 vCPU / 4 ГБ / 50 ГБ
   за ~650–1 100 ₽/мес (Timeweb, Beget, Selectel) или Yandex Cloud
   (VM + Managed PostgreSQL, ~2 600–3 500 ₽/мес). Зарубежные бесплатные
   тарифы (Cloudflare Workers + D1, Supabase, Vercel, Fly) для данных
   детей **не подходят** из-за локализации ПДн — их можно рассматривать
   только для анонимной телеметрии.

**Рекомендация по продукту:**

* идентификация — **код класса + псевдоним + токен профиля**, без имён,
  телефонов, e-mail и паролей у детей;
* согласие родителя — **обязательный шлюз**: без него класс не включается,
  данные не покидают телефон;
* соревнование — **недельный сезон**, метрика «звёзды за освоенные слова»
  (уникальные слова с `s ≥ 90`, не больше 10 в день), показываем
  **пьедестал + свою строку**, без публичного последнего места;
* школа — таблица классов **по среднему на активного ребёнка**, а не по
  сумме: иначе класс из 30 человек всегда бьёт класс из 10;
* телеметрия — 14 событий по белому списку, анонимный `install_id`,
  90 дней сырых данных, агрегаты — дольше.

**Что это стоит по времени (один разработчик, с ИИ-помощником):**

| Этап | Содержание | Оценка |
|---|---|---|
| 0 | решения, тексты согласий, модель угроз, юр. проверка | 3–5 дней |
| 1 | телеметрия и счётчики (без социалки) | 6–9 дней |
| 2 | класс: вход по коду, звёзды, таблица, удаление | 12–18 дней |
| 3 | кабинет учителя, школа, «домашка» | 12–18 дней |
| 4 | шифрованный бэкап профиля, перенос на новое устройство | 6–10 дней |
| 5 | родительские аккаунты, уведомления, сертификаты | 10–15 дней |

До состояния «можно заходить в школу» — примерно **45–65 рабочих дней**
включая проверки и юридический минимум. Первый полезный результат
(«сколько у нас пользователей и как они учатся») — **через 1–2 недели**.

**Что уже сделано в этой ветке:** референс-API на 10 маршрутов
(`server/`), 12 контрактных тестов, Dockerfile, пример Compose для NAS,
скрипт горячего бэкапа. Это не прод, но это проверенный контракт, на
котором можно провести пилот и не переписывать клиент при переезде
на PostgreSQL.

**Что нужно решить вам** — §13. Главные три: кто оператор ПДн
(физлицо / ИП / ООО / школа), какой класс берём в пилот и есть ли
бюджет ~1 000–1 500 ₽/мес на прод.

## 3. Пересмотр решения №5 («никаких лидербордов»)

Решение принималось, когда в приложении не было классов и сервера, а
единственным возможным рейтингом был глобальный публичный. Сейчас запрос
другой: **закрытое соревнование внутри класса**, которое учитель может
выключить. Это не то же самое, что публичный глобальный лидерборд.

### 3.1 Предлагаемая формулировка нового решения

> **№5a. Соревнования разрешены только закрытые и добровольные.**
> Внутри класса и школы, по коду, с согласия родителя, без публичного
> глобального рейтинга, без публичного «последнего места», без сравнения
> по скорости и без платных преимуществ. Учитель может приостановить
> таблицу; родитель может выключить участие для своего ребёнка.

### 3.2 Что остаётся запрещённым

| Запрет | Почему |
|---|---|
| глобальный рейтинг всех пользователей | сравнение несравнимого, давление, репутационные риски |
| публичное последнее место и «догоняй» | демотивация во 2 классе |
| рейтинг по времени/скорости | наказывает вдумчивых и детей с особенностями |
| рейтинг по серии дней | болезнь/поездка = потеря места, это не про учёбу |
| рейтинг по XP без оговорок | подсказка снижает XP (7 вместо 10) → выгодно не просить помощь |
| имена, фото, школа+класс+фамилия на публичной странице | идентификация ребёнка |
| платные бусты, «подписка на первое место» | токсичная монетизация |
| рейтинг школ по сумме | размер школы решает всё |

### 3.3 Почему метрика «звёзды за слова», а не XP

| Кандидат | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| XP | уже есть, привычно | подсказка снижает XP; сундуки и streak дают XP вне учёбы; легко «фармить» | нет |
| Число уроков | просто | короткий урок = больше уроков; повторение одного урока | нет |
| Точность | честно |наказывает осторожных; 1 ошибка из 3 = 67%; не отражает объём | нет |
| Серия дней | привычно | болезнь и поездки; давление «не потерять» | нет |
| **Уникальные освоенные слова (s ≥ 90) за неделю, ≤ 10/день** | прямо про результат; не зависит от подсказок; потолок убирает зубрёжку | слово можно «освоить» в одном уроке | **да** |
| Среднее по классу на ребёнка | честно для школы | сложнее объяснить детям | да, для школы |

Потолок 10 звёзд в день выбран так: базовый урок — 12–16 карточек, из них
новых слов обычно 4–8. 10 — это «хороший день», а не «весь день за
телефоном». Ребёнок, который занимается 20 минут, и ребёнок, который
занимается 2 часа, получают сопоставимый вклад в рейтинг; разница уходит
в личный прогресс, а не в борьбу.

## 4. Продуктовая модель

### 4.1 Роли

| Роль | Что видит | Чего не видит |
|---|---|---|
| **Ребёнок** | свои уроки; пьедестал класса; свою строку; цель класса | полный список класса, чужие ошибки, чужие профили |
| **Родитель** | прогресс своего ребёнка (как сейчас); переключатель «участвовать в классе»; что именно опубликовано; удаление данных | данные других детей |
| **Учитель** | свою таблицу класса, коды учеников, «кому нужна помощь»; пауза таблицы; домашку | ответы в свободной форме (их нет), чужие классы |
| **Школа** (позже) | таблицу классов, активность, сводку | персональные данные детей |
| **Оператор/разработчик** | агрегированные метрики, здоровье сервиса, ошибки, классы без имён | имена детей (их нет на сервере) |

### 4.2 Объекты

```
Школа (school_code, название)
  └── Класс (id, код входа, название «2 А», сезон, цель)
        ├── Ученик (child_id, псевдоним, аватар, токен, согласие)
        │     ├── День (day, звёзды, уроки, ответы, время)
        │     └── Освоенное слово (word_id, когда)
        └── Домашка (позже: lesson_ids, срок)
```

* **Школа** — не юридическое лицо и не аккаунт: это код и название,
  которые вводит оператор при создании класса. Проверка школы —
  организационная (договор), а не техническая.
* **Класс** — единица соревнования и сезон. Код класса — 6 символов
  без похожих букв (`A-Z`, `2-9`), 32⁶ ≈ 1,07 млрд комбинаций.
* **Ученик** — псевдоним + аватар из пресетов. **Имя профиля ребёнка
  не публикуется автоматически**: в приложении `profile.name` часто
  настоящее имя («Миша»), и отправлять его в класс нельзя. По умолчанию —
  «Ученик 7» или выбранный ребёнком пресет («Лисёнок», «Комета»).
* **Сезон** — неделя Пн–Вс. В конце — итоги, награды, сброс таблицы.
  Класс может жить несколько сезонов; история агрегатов остаётся.

### 4.3 Как выглядит соревнование

**Экран ребёнка** (новый пункт «Класс» на главной, появляется только
после входа):

```
┌──────────────────────────────────────┐
│  2 «А» · неделя 19–25 октября        │
│  Команда: 41 ⭐ из 100               │
│  ▓▓▓▓▓▓▓▓░░░░░░░  41%               │
├──────────────────────────────────────┤
│  🥇 Лисёнок        9 ⭐  3 дня       │
│  🥈 Комета         8 ⭐  4 дня       │
│  🥉 Ученик 7       7 ⭐  2 дня       │
│  …                                   │
│  Ты — 7 место      5 ⭐  2 дня       │
├──────────────────────────────────────┤
│  Как получить звезду?                │
│  Освой новое слово (без подсказки    │
│  тоже считается) — до 10 в день.     │
└──────────────────────────────────────┘
```

* Показываем **топ-3 и себя**. Полный список не отдаётся даже в API:
  это одновременно и защита от «последнего места», и защита от
  выкачивания ростера.
* Своя строка видна всегда, даже если ты 24-й. Это важно: ребёнок
  видит прогресс, а не только «я не в топе».
* Нет таймера, нет «вы потеряли место», нет push «догони».
* Командная цель: если класс набрал 100 ⭐, все получают облик сундука
  или значок. Это переводит конкуренцию в кооперацию и снижает травлю
  «из-за тебя мы проиграли».

**Экран учителя** (этап 3, отдельный лёгкий веб-клиент или раздел в PWA):

* создать класс, распечатать карточки с кодами и псевдонимами;
* таблица класса за неделю, «кто сколько освоил»;
* **«кому нужна помощь»**: слова с наибольшей долей ошибок, дети,
  у которых уроки обрываются на одном типе задания;
* пауза таблицы («неделя без рейтинга»), смена кода, удаление класса;
* домашка: «пройдите урок 7 до пятницы» — без оценки и без дедлайна
  в 23:59.

**Экран родителя:** «участие в классе» — выключено по умолчанию; при
включении показываем ровно то, что будет видно другим: псевдоним,
аватар, звёзды, дни. Кнопка «удалить данные из класса» и «выгрузить
свои данные» (выгрузка уже есть).

### 4.4 Сезоны, награды, школьная таблица

* **Неделя** — основной сезон: достаточно короткий, чтобы отставание
  не превращалось в приговор, и достаточно длинный, чтобы был смысл.
* **Награды:** место в пьедестале (без денежной ценности), значок
  профиля, облик сундука, командная награда. Кристаллы за рейтинг
  **не даём** — иначе появляется мотив накручивать.
* **Школа:** таблица классов по среднему числу звёзд на активного
  ребёнка. Класс попадает в таблицу, только если активных детей ≥ 5;
  иначе класс из двух человек с 10 звёздами объявляется лучшим в школе.
  Показываем не только место, но и активность — «2 А: 3,4 ⭐ на ученика,
  18 активных».
* **Школьные соревнования между школами** — не в первой версии: нужны
  проверка школ, модерация и договоры. Технически это тот же агрегат
  по `school_code`, но организационно рано.

### 4.5 Паритет с Учи.ру: что реально догонять

Учи.ру — платформа с олимпиадами, заданиями от учителя, статистикой по
классам и школам и портфолио (см. руководство пользователя и справку:
«рейтинги по классам и школам», статистика класса и отдельных учеников).
Догонять весь периметр бессмысленно; паритет нужен по тому, что просят.

| Возможность | Учи.ру | Сейчас у нас | В плане |
|---|---|---|---|
| Класс и список учеников | да | нет | этап 2 (коды) |
| Таблица класса | да | нет | этап 2 |
| Таблица школы / рейтинг классов | да | нет | этап 3 |
| Задания от учителя | да | нет (только уроки) | этап 3 («домашка») |
| Олимпиады | да, федеральные | нет | позже: «чемпионат слов» внутри школы, без федерального статуса |
| Портфолио и дипломы | да | значки, магазин | этап 5: PDF-сертификат класса |
| Статистика для родителя | да | локальный дневной отчёт | сервер добавит класс/школу |
| Работа офлайн | нет | **да** | сохранить |
| Цена | freemium/платно | бесплатно | решить в §13 |
| Психологическая нагрузка | есть рейтинги и таймеры | нет | не копировать |

**Вывод:** «не хуже» = закрытый классный рейтинг, понятная награда,
статистика учителю и родителю, работа без интернета. «Лучше» = офлайн,
отсутствие таймеров, отсутствие платного преимущества и прозрачные
правила.

### 4.6 Анти-стресс и анти-чит

| Риск | Мера |
|---|---|
| «я последний» | публично только топ-3 + своя строка; последнее место не показывается |
| «меня обогнали из-за подсказки» | звёзды не зависят от подсказок |
| «я заболел и потерял место» | недельный сброс, нет рейтинга по серии |
| «учитель заставит» | участие только с согласия родителя; учитель может выключить таблицу |
| накрутка повторным уроком | звезда за уникальное слово в день, повтор не даёт |
| перевод часов | серверное время, окно ±14 дней, событие «из будущего» отклоняется |
| подделка событий | потолок, дедупликация, проверка правдоподобия; этап 2 — манифест контента |
| «фарм» одним словом | уникальность `(ребёнок, день, слово)` |
| слив ростера | API отдаёт только топ-3 + себя; код класса меняется одной кнопкой |
| травля за проигрыш | командная цель + отсутствие публичного последнего места |

Честно: при желании ребёнок (или старший брат) может отправить
поддельные события. Ставки низкие — значок и место в классной таблице,
а не оценка и не приз. Поэтому защита эшелонированная, но не
криптографическая: потолки, дедупликация, серверное время, проверка
правдоподобия и учительский взгляд «10 звёзд за 2 минуты». На этапе 2
добавляется манифест контента: сервер знает, какие слова входят в урок,
и требует, чтобы за день был урок и верные ответы по этим словам.

## 5. Архитектура

### 5.1 Три плоскости и один принцип

```
┌────────────────────────── телефон ребёнка ──────────────────────────┐
│  PWA (GitHub Pages)                                                  │
│                                                                      │
│  уроки ── engine/SRS ── IndexedDB  ◄── источник истины для учёбы     │
│    │                        │                                        │
│    │                        ├── outbox (события класса и ответы)      │
│    │                        └── telemetry queue (анонимные события)  │
│    │                                    │                            │
│    └── UI не ждёт сеть ◄────────────────┘                            │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ HTTPS, CORS, Bearer-токен
                                   ▼
┌──────────────────────────── API (Docker) ────────────────────────────┐
│  /join  /sync  /board  /me  /telemetry  /admin/*                     │
│  валидация · лимиты · дедупликация · подсчёт звёзд · сезоны          │
└───────────────┬──────────────────────────────────┬───────────────────┘
                │                                  │
         SQLite (пилот)                     бэкап + офсайт
         PostgreSQL (прод)                  ежедневно / еженедельно
                │
        daily · mastered · answers · telemetry
                │
        ┌───────┴────────┐
        ▼                ▼
  экран «Класс»     админ-метрики
  (топ-3 + я)       (без имён)
```

Принцип: **ни один экран учёбы не ждёт сеть**. Все сетевые вызовы —
побочные, асинхронные, с таймаутом и деградацией в «локально».

### 5.2 Почему на старте нет полной синхронизации

Полная синхронизация профиля (два устройства, конфликты слияния,
сервер как источник истины) — это отдельный большой проект: сейф
прогресса в `src/platform/vault.ts` уже решает более важную задачу —
не потерять данные на одном устройстве. Если добавить серверную
синхронизацию «как в облаке», придётся пересматривать модель
конфликтов, миграции и приватность.

Поэтому поэтапно:

1. **Сейчас:** сервер получает только производные результаты
   (звёзды, уроки, ответы) — не весь профиль.
2. **Этап 4:** «шифрованный бэкап» — приложение выгружает существующий
   JSON-экспорт, шифрует его на устройстве (AES-GCM, ключ из кода
   восстановления, известного только родителю) и кладёт на сервер
   непрозрачным blob. Сервер не может прочитать прогресс; перенос на
   новое устройство — ввод кода. Это даёт 80% пользы облака без
   серверного знания о ребёнке.
3. Если когда-нибудь понадобится настоящая многопользовательская
   синхронизация (телефон + планшет одновременно) — это уже этап 5+
   и отдельное решение.

### 5.3 Поток одного урока

1. Ребёнок проходит урок офлайн; `finishLesson` обновляет профиль.
2. Приложение определяет **новые освоенные слова**: те, у которых
   `WordState.s` перешёл порог 90 в этом уроке (нужен снимок «до»).
3. В outbox кладутся события: `lesson`, `mastered` × N, `answer` × M,
   `active`. Каждому — UUID и время.
4. Очередь отправляется, когда есть сеть и вкладка активна: пачкой до
   100 событий, с идемпотентными id.
5. Сервер проверяет, применяет, возвращает `{accepted, duplicates,
   rejected, me}`.
6. Клиент обновляет локальный кэш таблицы; экран «Класс» показывает
   топ-3 + себя. Если сервер недоступен — экран показывает последнюю
   известную таблицу с пометкой «обновится позже».

### 5.4 Офлайн-очередь (outbox)

| Свойство | Решение |
|---|---|
| Хранилище | отдельный IndexedDB-стор `outbox` (не в основном профиле) |
| Формат | `{id, type, payload, createdAt, attempts, nextTryAt}` |
| Отправка | при старте, после урока, по `online`, раз в 5 минут при открытой вкладке |
| Пачка | ≤ 100 событий, ≤ 64 КБ |
| Ретраи | 5 с → 30 с → 2 мин → 10 мин → 1 ч (jitter), максимум 20 попыток |
| TTL | 14 дней; старше — отбрасываем с записью в диагностику |
| Дедупликация | `event.id` на клиенте (UUID v4), сервер помнит 30 дней |
| 401/410 | остановить очередь, снять привязку к классу, показать «класс недоступен» |
| 429 | уважать `Retry-After`, экспоненциальный backoff |
| 5xx/сеть | повторить позже, не терять |
| 413 | разбить пачку, не отбрасывать |
| Приватность | payload не содержит имени профиля и введённого текста |

Очередь не должна расти бесконечно: если 14 дней нет сети, события
старше TTL удаляются, а в «Родителям → Диагностика» появляется строка
«N событий класса не отправлены (нет сети)». Это честнее, чем тихо
держать мегабайты.

### 5.5 Что меняется на клиенте

| Файл | Изменение |
|---|---|
| `src/platform/social.ts` (новый) | вход по коду, токен, sync, board, выход, удаление |
| `src/platform/telemetry.ts` (новый) | `installId`, очередь, батчи, `app_open`, ошибки |
| `src/state/social.ts` (новый) | состояние класса, кэш таблицы, настройки приватности |
| `src/state/store.ts` | в `Profile` — `social?: {childId, token, classId, nickname, avatar}`; `answer`/`finishLesson` кладут события; выгрузка **не включает** токен |
| `src/ui/screens/ClassScreen.tsx` (новый) | таблица, вход, «как получить звезду», командная цель |
| `src/ui/parent/PrivacyTab.tsx` (новый) | участие, что публикуется, удаление, телеметрия |
| `src/ui/screens/HomeScreen.tsx` | пункт «Класс», если включено |
| `vite.config.ts` | `VITE_API_URL`, CSP `connect-src`, `NetworkOnly` для `/api` |
| `src/platform/pwa.ts` | не кэшировать ответы API; обновление не сбрасывает токен |

Ключевая деталь: **токен класса живёт в профиле ребёнка, а не в
настройках устройства**. В одном браузере могут быть профили двух детей
(и это уже поддерживается) — у каждого свой класс, свой токен и своё
согласие. `installId` телеметрии — наоборот, один на браузер/устройство.

Выгрузка профиля (`Родителям → Прогресс`) **не должна содержать
токен**: это bearer-credential, файл выгрузки часто пересылают. При
импорте привязка к классу не восстанавливается — нужно войти заново
(и это объясняется в интерфейсе).

### 5.6 Флаги и постепенное включение

* Сборка: `VITE_SOCIAL=1`, `VITE_API_URL=https://api.example.ru`.
* Без флага экран «Класс» отсутствует, сетевых вызовов нет — поведение
  сегодняшнего приложения.
* Runtime-настройка `settings.privacy.social` (по умолчанию `off`) и
  `settings.privacy.telemetry` (по умолчанию `on`, анонимно; можно
  выключить).
* Kill switch: если сервер отвечает `503 social_disabled`, клиент
  скрывает «Класс» и показывает «соревнования временно выключены».
* Откат: убрать флаг в сборке. Локальные данные не страдают, потому
  что социальный слой ничего не пишет в учебный профиль, кроме
  собственной привязки.

### 5.7 Серверные компоненты

| Компонент | Пилот (эта ветка) | Прод |
|---|---|---|
| HTTP | `node:http`, 10 маршрутов | Fastify/Node или тот же `node:http` |
| Валидация | ручная, минимальная | zod-схемы, общие с клиентом |
| БД | SQLite (`node:sqlite`), WAL | PostgreSQL 16 |
| Миграции | `PRAGMA user_version` | Drizzle/Prisma + expand/contract |
| Аутентификация | админ-токен, токены детей | + учительские аккаунты (Argon2id, TOTP) |
| Логи | JSON-строки, без тела/IP | pino + ротация, 14 дней |
| Метрики | SQL + `/v1/admin/metrics` | Metabase/Grafana + те же вьюхи |
| Бэкап | `node:sqlite backup` + cron DSM | pgBackRest/WAL-G + офсайт |
| Мониторинг | healthcheck Docker | Uptime Kuma + алерт в Telegram |
| TLS | DSM Reverse Proxy / Cloudflare Tunnel | Caddy/nginx + Let's Encrypt |
| Деплой | Container Manager, `docker compose up -d` | systemd/compose + CI |

Почему не «сразу Kubernetes/микросервисы»: один процесс и одна база
обслуживают десятки тысяч детей (расчёт в §7.8). Сложность здесь
увеличивает риск, а не надёжность.

Оговорка про `node:sqlite` в Node 22: модуль помечен экспериментальным
(в логах будет `ExperimentalWarning`, мы глушим его флагом
`--disable-warning`). Для нашего использования API стабилен, но это
ещё одна причина не строить на нём многолетнюю историю: при переезде
на PostgreSQL вопрос снимается. Формат данных и контракт API при
переезде не меняются.

### 5.8 Правила для service worker и CSP

* `NetworkOnly` для `https://api.*/v1/*`: ответы класса не кэшируются,
  иначе ребёнок увидит вчерашнюю таблицу как сегодняшнюю.
* Токены не попадают в Cache Storage и в URL (только заголовок).
* `connect-src` в CSP: `'self' https://api.example.ru`; всё остальное
  запрещено.
* API на отдельном origin (`api.example.ru`), чтобы не пересекаться
  с областью действия SW на GitHub Pages.
* CORS: белый список origin (`https://artignat2000.github.io`,
  `http://localhost:5173`, позже собственный домен). Без `*`.

## 6. Идентификация, согласие, приватность

### 6.1 Три варианта идентификации

| | A. Код класса + токен устройства | B. Код класса + карточка ученика | C. Полные аккаунты |
|---|---|---|---|
| Как входит | вводит код класса один раз | вводит свой код с карточки, выданной учителем | e-mail/телефон + пароль |
| Что на сервере | псевдоним, аватар, результаты | то же + связь «карточка ↔ место в журнале» (у учителя) | ПДн взрослого, привязка ребёнка |
| Плюсы | проще всего, 30 секунд | учитель знает, кто есть кто; перенос на другое устройство | восстановление, мультиустройство, оплата |
| Минусы | потеря устройства = новый ученик; учитель не знает, кто «Ученик 7» | нужно печатать карточки | тяжело, ПДн, пароли детям, 152-ФЗ |
| Вердикт | **пилот** | **целевая модель этапа 3** | позже, только для родителя |

**Рекомендация:** начать с A, но сразу проектировать API под B:
`/v1/join` уже принимает код класса; на этапе 3 добавляется
`/v1/join` с персональным кодом карточки (`roster_code`), который
выдаёт учитель. Никаких имён на сервере и в модели B: карточка
содержит код, псевдоним и (опционально) номер места; соответствие
«код → ребёнок» хранится у учителя на бумаге или в его локальном
файле.

### 6.2 Как выглядит вход

1. Учитель (или оператор пилота) создаёт класс, получает код `K7M2QX`
   и печатает карточки: `K7M2QX` + псевдоним + аватар.
2. Ребёнок открывает приложение → «Класс» → вводит код.
3. Появляется экран согласия: короткий текст, кто оператор, что
   публикуется, кнопка «Родитель разрешил» (или «У меня есть согласие»).
   Без нажатия дальше нельзя.
4. Приложение создаёт/использует локальный профиль, отправляет
   `/v1/join`, получает токен и сохраняет его **в профиле**.
5. Экран класса: пьедестал, своя строка, правила.

Если интернета нет в момент входа — вход откладывается, обучение
продолжается; на экране «Класс» написано «подключимся, когда появится
сеть».

### 6.3 Согласие: состояния и версии

| Состояние | Что видит ребёнок | Что уходит на сервер |
|---|---|---|
| Не участвует (по умолчанию) | обычное приложение, пункта «Класс» нет | только анонимная телеметрия (если включена) |
| Согласие дано | «Класс» + таблица | псевдоним, аватар, звёзды, ответы |
| Согласие отозвано | «Класс» исчезает, данные удалены | ничего |
| Версия текста устарела | просьба показать родителю новую версию | ничего до подтверждения |

* Версия текста — строка даты (`2026-10-21`), хранится и на клиенте,
  и на сервере. Изменение текста = новая версия = повторное согласие.
* Согласие фиксируется на сервере: `consent_version`, `consent_at`,
  кто подтвердил (`parent`/`teacher` — для школы). Это не заменяет
  бумажное согласие, если его требует школа, но даёт журнал.
* Для школы: согласия собирает школа (она оператор), сервис —
  обработчик по поручению. Тогда в приложении достаточно отметки
  «согласие получено школой», а реквизиты — в договоре.
* Для «родитель поставил себе»: оператор — владелец сервиса,
  согласие даётся в приложении, политика опубликована на сайте.

### 6.4 Минимизация данных

| Поле | Зачем | Срок | Кто видит |
|---|---|---|---|
| `child_id` (случайный) | связать события | до удаления/конца класса + 30 дней | сервер, учитель (косвенно) |
| псевдоним, аватар | таблица | там же | класс |
| `consent_version`, `consent_at` | доказать основание | 3 года после окончания | оператор |
| `daily` (звёзды, уроки, ответы, время) | рейтинг и качество | сезон + 12 месяцев | ребёнок, учитель |
| `mastered` (слово, день) | звёзды | сезон + 12 месяцев | ребёнок, учитель |
| `answers` (слово, тип, верно/нет, подсказка, мс) | качество контента | **90 дней** | разработчик (агрегат) |
| `telemetry` (`install_id`, событие, свойства) | продукт | **90 дней** сырые, агрегаты — 24 месяца | разработчик |
| IP-адрес | лимиты | **не хранится**, только в памяти | никто |
| логи | здоровье | 14 дней, без тела и IP | оператор |
| `audit` | безопасность | 12 месяцев | оператор |

В API **нет** полей для имени, фамилии, телефона, e-mail, даты рождения,
адреса, школы в смысле «конкретный ребёнок», фото, геолокации, класса
с фамилией учителя. Если поле не описано в схеме — оно не принимается.

### 6.5 Чего мы не собираем и почему

* **Имя профиля ребёнка.** Оно уже есть локально и часто настоящее;
  автоматическая публикация — утечка. Псевдоним выбирается отдельно.
* **Свободный текст ответов.** Приложение проверяет выбор букв/слов;
  текст не нужен, а его хранение создаёт риск.
* **Школьный журнал.** Список класса, ФИО, оценки — не наша зона.
* **Рекламные идентификаторы, cookie-трекеры, пиксели.** Нет.
* **Геолокация, микрофон, камера, контакты.** Нет.
* **Push-уведомления детям.** Позже — только родителю и только
  по явному согласию.

### 6.6 Псевдонимы и модерация

* Пресеты: «Лисёнок», «Комета», «Кристалл», «Сова», «Тигр» и т.п.
  (20–30 вариантов) + аватар из существующих 10.
* Свободный ввод — с ограничением 2–20 символов, без ссылок, `@`,
  управляющих символов. Блок-лист — минимальный; полноценная
  модерация появится, когда появится публичность (сейчас её нет,
  таблицу видят только одноклассники).
* Псевдоним уникален в классе (без учёта регистра): иначе в таблице
  две «Звёздочки». При занятом псевдониме вход отвечает `409
  nickname_taken` и предлагает добавить цифру. При переустановке
  приложения ребёнок входит заново; старую запись учитель может
  удалить, тогда псевдоним освобождается.
* Кнопка «Пожаловаться» в строке таблицы → запись в `audit` +
  уведомление оператору в Telegram; учитель может переименовать
  или исключить.
* Учитель может выключить свободные псевдонимы и оставить пресеты.

### 6.7 Права ребёнка и родителя

| Право | Как реализуется |
|---|---|
| знать, что публикуется | экран «Приватность» со списком полей |
| выгрузить данные | существующая выгрузка JSON + серверный экспорт по запросу |
| исправить псевдоним | в профиле, до отправки и после |
| удалить данные класса | `DELETE /v1/me` + удаление привязки на клиенте |
| отозвать согласие | выключатель; данные удаляются, участие прекращается |
| не участвовать | по умолчанию выключено |
| удалить всё | «Родителям → Начать заново» + серверное удаление |

### 7.3 Ошибки и поведение клиента

| HTTP | Код | Что делает клиент |
|---|---|---|
| 400 | `consent_required`, `bad_nickname`, `bad_code` | показывает подсказку, не ретраит |
| 401 | `token_invalid` | снимает привязку, «класс недоступен», обучение продолжается |
| 404 | `class_not_found` | просит проверить код |
| 409 | `consent_outdated`, `nickname_taken` | новый текст согласия / выбрать другой псевдоним |
| 410 | `class_archived` | выходит из класса, данные локально остаются |
| 413 | `body_too_large` | дробит пачку |
| 429 | `too_many_*` | backoff по `Retry-After` |
| 5xx | `internal` | ретрай с backoff, экран не блокируется |

Сервер не отвечает «ок» на отклонённое событие: `rejected` содержит
причину, а повторная отправка с тем же id не считается дублем, если
событие не было принято. Это важно для очереди.

### 7.4 Схема данных (ядро)

Полная схема — [`server/src/db.mjs`](../../server/src/db.mjs).
В PostgreSQL те же таблицы, кроме `WITHOUT ROWID`-оптимизаций:

```sql
classes(id, school_code, school_name, label, code UNIQUE, goal_stars,
        created_at, archived_at)

children(id, class_id → classes, nickname, avatar,
         token_hash UNIQUE, consent_version, consent_at,
         created_at, last_seen_at, deleted_at)

daily(child_id, day, stars, lessons, tasks, correct, wrong,
      active_seconds, updated_at, PRIMARY KEY(child_id, day))

mastered(child_id, day, word_id, at,
         PRIMARY KEY(child_id, day, word_id))      -- уникальность звезды

answers(id, child_id, ts, day, word_id, kind, correct, hint, ms)

telemetry(id, install_id, at, day, app_version, name, props)
seen_events(child_id, id, at, PRIMARY KEY(child_id, id))
audit(id, at, action, detail)
```

Почему `mastered` с первичным ключом `(child_id, day, word_id)`:
звезда — это свойство «слово освоено в этот день», повторный урок
не добавляет. `daily.stars` — кэш `MIN(10, COUNT(mastered))`, чтобы
таблица считалась одним запросом.

### 7.5 Периоды, часовые пояса, сезоны

* День — строка `YYYY-MM-DD`; неделя — Пн–Вс по `Europe/Moscow`.
* Клиент присылает свой локальный день, сервер принимает его только
  в окне `[сегодня−14, сегодня+1]`: Камчатка и Калининград — одна
  страна, а сервер один.
* В будущем — часовой пояс школы в `classes.timezone`; для пилота
  Москвы достаточно.
* `period=week` — текущая неделя, `30d` — последние 30 дней,
  `all` — весь сезон. Сброс сезона не удаляет `daily`: меняется только
  окно запроса, поэтому история и награды не теряются.

### 7.6 Идемпотентность и версии

| Версия | Где | Зачем |
|---|---|---|
| `consentVersion` | сервер + клиент | повторное согласие при изменении текста; клиент берёт актуальную из `/healthz` |
| `schemaVersion` | `PRAGMA user_version` / миграции | обновление БД |
| `contentHash` | этап 2 | сервер знает список слов и уроков |
| `event.id` | клиент | дедупликация при ретраях |
| `appVersion` | телеметрия | доля старых сборок |

Обновление схемы — только expand/contract: сначала добавить поле/таблицу,
потом переключить код, потом удалить старое. Никаких «пересоздадим базу»
на живом классе.

### 7.7 Лимиты

| Что | Лимит | Почему |
|---|---|---|
| тело запроса | 64 КБ | защита от мусора |
| событий в sync | 100 | размер пачки и время транзакции |
| событий в telemetry | 200 | то же |
| sync на ребёнка | 240/мин | нормальный клиент шлёт 1–2 пачки |
| join с одного IP | 60/10 мин | школьный NAT: целый класс должен войти |
| telemetry на install | 60/мин | защита от цикла |
| длина псевдонима | 2–20 | интерфейс и модерация |
| `wordId` | 2–32, буквы/цифры/`_`/`-` | совместимо с `g2_Москва` |

Код класса — 6 символов из 32: перебор при 60 попытках/10 мин
бесперспективен, но на проде добавляется лимит на неудачные попытки
по IP и уведомление оператору при всплеске.

### 7.8 Нагрузка и объём

Расчёт на одного активного ребёнка в день: ~1,5 урока × 12 карточек =
18 ответов × ~250 Б ≈ 4,5 КБ событий; 4 запроса (2 sync + 2 board);
10 телеметрических событий ≈ 2,5 КБ.

| | 50 детей (пилот) | 1 000 активных | 10 000 активных |
|---|---|---|---|
| запросов в день | ~200 | ~4 000 | ~40 000 |
| средний rps | < 0,01 | 0,05 | 0,5 |
| пик, средний за 18:00–21:00 | < 0,01 | ~0,1 | ~1 |
| всплеск (класс закончил урок) | ~5 rps | ~10 rps | ~30 rps |
| сырые данные в день | 0,4 МБ | 7 МБ | 70 МБ |
| сырые за 90 дней | 36 МБ | 0,6 ГБ | 6,3 ГБ |
| с индексами | ~0,1 ГБ | ~1 ГБ | ~10 ГБ |
| БД | SQLite | SQLite/Postgres | PostgreSQL |
| железо | NAS 2 ГБ | 2 vCPU/4 ГБ | 2–4 vCPU/8 ГБ |

Телеметрия даёт примерно столько же. Вывод: **узкое место — не
нагрузка, а юридические и продуктовые вопросы**. 10 000 активных
детей в день — это десятки тысяч установок, и даже тогда хватает
одного узла; горизонтальное масштабирование понадобится не раньше
сотен тысяч.

### 7.9 Бэкапы и восстановление

| Что | Пилот | Прод |
|---|---|---|
| Частота | ежедневно 03:00 | ежечасно (SQLite backup) / WAL-архив (PG) |
| Хранение | 14 копий на NAS | 14 дней + 12 недель + 12 месяцев |
| Офсайт | раз в неделю на внешний диск | Object Storage в РФ, шифрование |
| Проверка | раз в месяц восстановить и открыть | раз в месяц + автоматический тест |
| RPO | 24 часа | ≤ 1 час |
| RTO | 2 часа | 1 час |
| Шифрование | LUKS/архив с паролем | age/gpg + ключ вне сервера |

Бэкап на том же диске — не бэкап. В чек-листе §14F это отдельный
пункт: «копия лежит на другом носителе и проверена восстановлением».

## 8. Аналитика для разработчиков

### 8.1 Какие вопросы должны получать ответ

| Вопрос | Метрика | Зачем |
|---|---|---|
| Сколько у нас пользователей? | installs, DAU/WAU/MAU, дети, классы, школы | рост, отчётность, решения о хостинге |
| Возвращаются ли? | D1/D7/D30 retention, серия активных дней | удержание |
| Доходят ли до урока? | воронка install → профиль → урок 1 → урок 5 | барьеры входа |
| Где бросают? | завершённость урока, выход по типу задания | UX |
| Какие слова трудные? | доля ошибок по `word_id` | правки мнемоник и предложений |
| Какие типы заданий трудные? | точность по `kind` | методика и баланс |
| Помогает ли подсказка? | hint rate, точность с/без | решение №2 (7 XP) |
| Не сломали ли офлайн? | sync_failed, размер очереди, доля офлайн-сессий | надёжность |
| Какая версия у детей? | распределение `appVersion` | обновления PWA |
| Не читерят ли? | звёзды/минута, аномалии | честность таблицы |

### 8.2 События (белый список)

Все имена и свойства проходят серверный белый список; всё остальное
отбрасывается. В `props` — только плоские значения, без свободного
текста.

| Событие | Когда | Свойства (макс. 12) |
|---|---|---|
| `first_run` | первый запуск | `version` |
| `app_open` | старт приложения | `screen`, `standalone` |
| `profile_created` | создан профиль | `avatar` (id, не имя) |
| `lesson_start` | начало урока | `lesson_id`, `size` |
| `lesson_finish` | конец урока | `lesson_id`, `tasks`, `correct`, `pct`, `seconds` |
| `review_finish` | конец повторения | `words`, `correct` |
| `task_answer` | ответ | `word_id`, `kind`, `correct`, `hint`, `ms` |
| `hint_used` | нажата подсказка | `kind` |
| `chest_open` | сундук | `kind`, `awake` |
| `shop_buy` | покупка | `item_kind`, `price` |
| `pwa_install` | установка на экран | `platform` |
| `update_applied` | обновление | `from`, `to` |
| `client_error` | ошибка JS | `code`, `where` (без stack) |
| `sync_failed` | не удалось отправить | `status`, `attempt` |

**Не отправляем:** имя профиля, псевдоним, текст ответа, e-mail, IP,
`navigator.userAgent` целиком (только `platform`), URL, содержимое
IndexedDB, `localStorage`.

### 8.3 KPI и определения

| Метрика | Формула | Комментарий |
|---|---|---|
| Install | уникальный `install_id` за период | не равен «ребёнку»: переустановка = новый |
| DAU | уникальные `install_id` с `app_open` за день | по телеметрии |
| WAU/MAU | то же за 7/30 дней | скользящее окно |
| Ребёнок | `children` без `deleted_at` | по классам, не по установкам |
| Класс/школа | активные `classes` / `school_code` | для отчёта |
| D1 retention | доля установок дня X, вернувшихся на X+1 | когорты по первому запуску |
| D7/D30 | то же через 7/30 дней | |
| Completion | `lesson_finish / lesson_start` | по уроку |
| Accuracy | `correct / answers` | по слову, типу, версии |
| Hint rate | ответы с `hint / answers` | |
| Hard word | `errorRate` при ≥ 5 ответах | порог k-анонимности |
| Sync health | `sync_failed / sync` | |
| Version share | installs по `appVersion` | |

Важно: телеметрию можно выключить. Тогда цифры — это «нижняя оценка»,
а не вся аудитория. В интерфейсе админки пишем «по согласившимся», а
для отчёта «сколько пользователей» используем ещё и серверные счётчики
классов/детей.

### 8.4 Контур качества контента

1. Ночной агрегат: `word_id → ответы, ошибки, подсказки, среднее время`.
2. Порог: слово попадает в отчёт, если ответов ≥ 5 (иначе это один
   ребёнок, а не свойство слова).
3. Раз в неделю: топ-10 трудных слов → сверить мнемонику, предложение,
   картинку, опасную букву. Правка — контент-пакет, `content:check`.
4. До/после: сравнить `errorRate` на когорте новых ответов; не
   объявлять победу по 3 ответам.
5. Тип задания с точностью < 60% — пересмотреть формулировку/варианты,
   а не «дети тупые».
6. Всё это — агрегаты; ни один отчёт не показывает ребёнка.

Это, пожалуй, самая ценная часть аналитики: она улучшает продукт без
того, чтобы кого-то профилировать. Для 94 слов и 16 уроков недельный
отчёт реально меняет контент.

### 8.5 Хранение, выборка, стоимость

* Сырые `answers` — 90 дней; `telemetry` — 90 дней; агрегаты — 24 месяца.
* Партиционирование по дню (в PG) или удаление по `WHERE day < ?`.
* При росте > 100 тыс. событий/день — выборка `task_answer` 20–50%,
  но `lesson_finish` и `first_run` — 100%.
* `props` — JSONB в PG, TEXT в SQLite; индексы только по `(day, name)`
  и `(word_id, day)`.
* Стоимость хранения: 10 ГБ в Object Storage РФ — десятки рублей
  в месяц; на VPS диск 50–80 ГБ входит в тариф.

### 8.6 Дашборды

**MVP (этап 1):** страница `/admin` (без фреймворка, один HTML+fetch
или серверный шаблон) с цифрами из `/v1/admin/metrics`: установки,
DAU-график, уроки, точность, топ трудных слов, версии. Достаточно для
решений и не требует Metabase.

**Дальше:** Metabase в Docker (≈ 1 ГБ RAM) на том же VPS или отдельно;
читает только вьюхи `metrics_*`, не таблицы. Альтернатива — Grafana
(метрики + алерты), если нужен мониторинг, а не исследование.

**Алерты (Telegram-бот):**
* сервер не отвечает 5 минут;
* ошибок 5xx > 1% за 15 минут;
* `sync_failed` > 10% за час;
* диск > 80%;
* бэкап не создан за 26 часов;
* всплеск неудачных `join` (перебор кодов).

### 8.7 Приватность аналитики

* `install_id` — случайный UUID v4, генерируется на устройстве, не
  связан с `child_id` и не передаётся в социальный слой.
* Нет cross-site трекинга, нет рекламных SDK, нет fingerprinting.
* `props` проходят белый список ключей и значений.
* Отчёты — только агрегаты; выгрузка сырых строк — только оператору,
  по журналу доступа.
* k-анонимность: слова и типы заданий показываем при ≥ 5 ответах;
  классы в школе — при ≥ 5 активных; всё, что меньше, — скрываем.
* Сроки: 90 дней сырых, 24 месяца агрегатов; удаление по расписанию.
* Отключение телеметрии не ломает приложение и не влияет на обучение.

## 9. Где размещать: варианты, цены, рекомендация

### 9.1 Вариант A — Synology (ваш NAS), пилот

**Как:** DSM 7.2+, Container Manager → «Проект» → Compose из
[`server/docker-compose.example.yml`](../../server/docker-compose.example.yml).
Один контейнер API, том `/volume1/docker/slovo-api/data`, SQLite.
Порт 8080; наружу — DSM Reverse Proxy с сертификатом Let's Encrypt
(через `*.synology.me` или свой домен) либо Cloudflare Tunnel.

| Плюсы | Минусы |
|---|---|
| 0 ₽ за железо, всё под рукой | домашний интернет и электричество — единая точка отказа |
| полный контроль и приватность | нет SLA; отпуск/переезд = простой |
| просто бэкапить на внешний диск | CGNAT/динамический IP (решается туннелем) |
| быстро проверить продукт | HDD и UPS — дополнительные деньги |
| Docker без абонплаты | Synology обновляется — контейнер может не встать |

**Кому:** пилот на своём классе/семье, 2–6 недель, до 100 детей.
**Стоимость:** 0 ₽/мес + электричество ~100–200 ₽/мес + домен
~200–1 000 ₽/год. Внешний диск для бэкапа — 5–8 тыс. ₽ разово.

**Важно:** для школы Cloudflare Tunnel означает прохождение трафика
через зарубежную инфраструктуру — это вопрос трансграничной передачи.
Для пилота на своих данных допустимо; для реального класса —
российский хостинг или письменное заключение юриста.

### 9.3 Вариант C — Yandex Cloud

Два подварианта:

1. **VM + Managed PostgreSQL.** VM 2 vCPU/4 ГБ ≈ 1 800 ₽/мес, диск
   50 ГБ HDD ≈ 114 ₽, публичный IP ≈ 150–200 ₽, Managed PostgreSQL
   `b1.nano` ≈ 504 ₽ + диск 20 ГБ ≈ 46 ₽ + бэкапы. Итого
   **≈ 2 600–3 500 ₽/мес**. Плюс: managed-бэкапы, SLA, российские ЦОД.
2. **Serverless Containers + Managed PostgreSQL.** Первые
   1 000 000 вызовов, 10 ГБ·ч RAM и 5 vCPU·ч в месяц не тарифицируются;
   при нашем профиле API почти бесплатен, остаётся БД
   **≈ 700–1 200 ₽/мес**, но появляются cold start и ограничения
   на размер/время.

| Плюсы | Минусы |
|---|---|
| managed-БД, бэкапы, SLA | дороже VPS в 2–3 раза |
| российская юрисдикция | сложнее калькулятор и квоты |
| гранты: 4 000 ₽/60 дней; Cloud Boost до 50 000 ₽/180 дней | грант не отменяет обязанностей оператора |
| масштабирование по кнопке | vendor lock-in на сервисы |

**Кому:** школа/фонд требует договор и SLA; несколько школ; нет
желания администрировать БД. Грант позволяет первые месяцы прожить
почти бесплатно.

### 9.4 Вариант D — зарубежные бесплатные платформы

социальный слой в двух местах — усложнение ради экономии 1 000 ₽/мес;

### 9.5 Вариант E — вообще без сервера

Класс собирает результаты вручную: учитель сканирует QR-коды с экранов,

**Резервный вариант** для школ без интернета и для демонстрации
«мы можем без облака», но не основной путь.

## 10. Право, безопасность, доверие

> Это не юридическое заключение. Перед реальным классом нужен юрист,
> знакомый с 152-ФЗ; ниже — карта вопросов и минимальный набор мер.

### 10.1 152-ФЗ: что важно именно здесь

| Вопрос | Почему критичен | Что делать |
|---|---|---|
| Кто оператор? | от этого зависят уведомление, политика, договоры | определить: владелец сервиса (ИП/ООО) или школа |
| Согласие законного представителя | за детей до 14 лет согласие даёт законный представитель (ст. 9 152-ФЗ) | отдельный документ, не пункт в оферте (с 01.09.2025) |
| Локализация | первичная запись ПДн — в РФ | российский хостинг, без зарубежных БД |
| Уведомление РКН | обязанность оператора | подать до начала обработки; штраф за пропуск |
| Политика обработки | должна быть доступна | страница на сайте + ссылка в приложении |
| Поручение обработки | если школа — оператор, сервис — обработчик | договор + поручение (ст. 6 ч. 3) |
| Оценка вреда | обязанность оператора | короткий документ, чек-лист в §14C |
| Утечка | уведомление в 24 часа | план реагирования, контакты, логи |

Штрафы (ст. 13.11 КоАП, редакция 420-ФЗ; ориентиры на 2026):
обработка без согласия — **300–700 тыс. ₽** для юрлица, повторно
1–1,5 млн; отсутствие политики — 30–60 тыс.; неуведомление РКН —
100–300 тыс.; утечка 1–10 тыс. субъектов — 3–5 млн; 10–100 тыс. —
5–10 млн; свыше 100 тыс. — 10–15 млн; неуведомление об утечке —
1–3 млн; повторная утечка — 1–3% годовой выручки, не менее 20 млн
и не более 500 млн. Нарушение локализации по разным обзорам — от 1 до 6 млн,
повторно — до 18 млн. Цифры взяты из обзоров законодательства, а не
из первоисточника; перед школой их нужно сверить с актуальной
редакцией КоАП.

**Минимизация — главная защита.** Мы не храним имена, телефоны,
e-mail, адреса, фото и геолокацию. Даже если псевдоним и результаты
остаются ПДн (связаны с классом и учителем), объём и вред несопоставимы
с базой «ФИО + телефон + оценки». Это не отменяет обязанностей, но
снижает и риск, и стоимость соответствия.

### 10.2 Кто оператор в трёх сценариях

| Сценарий | Оператор | Что нужно |
|---|---|---|
| Родитель ставит себе и вводит код класса | владелец сервиса (ИП/ООО/физлицо) | уведомление РКН, политика, согласие в приложении, российский хостинг |
| Учитель ведёт класс в школе | школа (оператор), сервис — обработчик | договор, поручение, согласия собирает школа, политика сервиса |
| Школьная платформа / район | школа/орган управления | договор, 44-ФЗ/223-ФЗ, возможно конкурс |

Для пилота на своём классе: письменные согласия родителей + политика
на сайте + российский хостинг. Для продажи школе: ИП/ООО, договор,
поручение, уведомление РКН, юрист.

### 10.3 Модель угроз (STRIDE-lite)

| Угроза | Пример | Мера |
|---|---|---|
| **S**poofing | чужой вводит код класса | 6-символьный код, лимиты, смена кода, журнал |
| **T**ampering | подделка событий/звёзд | потолки, дедупликация, серверное время, манифест контента (этап 2) |
| **R**epudiation | «это не я отправил» | `audit`, токен на профиль, журнал входов |
| **I**nfo disclosure | слив ростера через API | только топ-3 + себя; нет имён; TLS; логи без тела |
| **D**oS | флуд sync/join | лимиты, 64 КБ тело, backoff, Cloudflare/провайдер L3/L4 |
| **E**levation | угон админ-токена | 32+ символа, только в env, 2FA на DSM, VPN/ ограничение по IP |
| Supply chain | вредоносный npm-пакет | у сервера нет зависимостей; клиент — lock-файл, аудит |
| Ошибка оператора | `rm -rf`, миграция | бэкапы + проверка восстановления, read-only контейнер, staging |

### 10.4 Технические меры

* TLS 1.2+, HSTS, HTTP→HTTPS, современные шифры (Caddy/DSM).
* Токены — 32 случайных байта, в БД только SHA-256; сравнение
  постоянное по времени; админ-токен — отдельный, не в коде и не в git.
* Пароли учителей (этап 3) — Argon2id, TOTP по желанию, без e-mail:
  восстановление через оператора.
* CORS — белый список, не `*`; CSP `connect-src` только API.
* Лимиты и таймауты на всех маршрутах; тело ≤ 64 КБ.
* Контейнер: non-root, `read_only`, `no-new-privileges`, без лишних
  портов; БД не публикуется.
* Секреты — `compose.env` с `chmod 600`, не в образе и не в git.
* Бэкапы шифруются; ключ хранится отдельно от сервера.
* Логи — без IP, тела, токенов; 14 дней; доступ по SSH-ключу.
* Обновления: DSM и образ — по календарю; `npm audit` для клиента;
  фиксированные теги образов.
* Мониторинг: healthcheck, Uptime Kuma снаружи, алерты в Telegram.
* Аудит действий оператора: создание/смена кода/удаление класса.
* Резервный админ-доступ: второй токен в менеджере паролей; при
  компрометации — `rotate` и удаление класса.

### 10.5 Реагирование на инцидент

1. **0–1 час:** остановить утечку (отозвать токены, закрыть порт,
   поднять из бэкапа), сохранить логи, не «прибирать» следы.
2. **1–24 часа:** оценить категории и число субъектов; уведомить
   РКН (24 часа с момента обнаружения), оповестить оператора/школу.
3. **24–72 часа:** внутренний разбор: как, что, кто; исправление;
   решение об уведомлении родителей/учителей.
4. **Далее:** постмортем без поиска виноватых, обновление мер,
   проверка, что исправление покрыто тестом или процессом.

Контакты и шаблон уведомления — в §14D. Если данных детей нет
(только анонимная телеметрия), инцидент всё равно разбирается, но
обязанности по 152-ФЗ могут не применяться — это фиксируется
в журнале.

### 10.6 Детская безопасность и модерация

* Нет чата, личных сообщений, комментариев, лайков, подписок.
* Нет внешних ссылок с экрана класса; всё, что открывается, — через
  родительский раздел.
* Псевдонимы — пресеты + блок-лист; жалоба → оператор.
* Учитель может исключить ребёнка из таблицы и скрыть класс.
* Нет публичных профилей в интернете: таблица доступна только по
  токену ребёнка из этого класса; поисковики не индексируют API.
* Нет рекламы, микротранзакций и «соревнований за деньги».

Тогда добавляются GDPR (ЕС), UK GDPR, COPPA (США), возрастные

* Смоук: приложение работает при выключенном API (как сейчас).

**Готово, когда:** на `/admin` видны установки, DAU, уроки, точность,
топ трудных слов; в базе нет ни одного имени; офлайн не сломан.

### 11.4 Этап 2 — класс (12–18 дней)

**Клиент:**
* `profile.social` (childId, token, classId, nickname, avatar).
* Экран «Класс»: вход, согласие, пьедестал + я, правила, командная цель.
* Расчёт новых освоенных слов: снимок `s` до урока → после; события
  `mastered` только для перешедших 90.
* Outbox: все события, ретраи, TTL, диагностика.
* Родительский экран приватности: участие, что публикуется, удаление.
* Kill switch и поведение при 401/410/429/5xx.

**Сервер:**
* Всё уже есть в `server/` (join, sync, board, delete).
* Добавить: `contentHash`/манифест слов и уроков (этап 2, можно позже
  в этом же этапе); проверку правдоподобия (10 звёзд за < 2 минут —
  флаг учителю).
* Лимиты на неудачные join, `Retry-After`.

**Проверки:**
* 25 детей входят за < 10 минут (тест на реальном классе).
* Таблица обновляется после sync; при выключенной сети показывает
  кэш и не врёт.
* Потолок 10/день, дубли не накручивают, удаление работает.
* Тест: сервер лежит → уроки проходятся, ошибок в консоли нет.
* Мобильный трафик: одна пачка < 64 КБ, отправка не блокирует UI.

**Готово, когда:** класс из 20+ детей живёт неделю, учитель видит
таблицу, ни один ребёнок не «потерял» прогресс.

### 11.5 Этап 3 — учитель, школа, домашка (12–18 дней)

**Учитель:**
* Аккаунт: логин/пароль (Argon2id), без e-mail; восстановление через
  оператора; TOTP по желанию.
* Создание класса, генерация карточек (PDF: код + псевдоним + аватар),
  печать, смена кода, архив класса.
* Таблица класса, «кому нужна помощь» (слова/типы заданий), пауза
  таблицы, переименование/исключение.
* Домашка: выбрать урок/слова, срок, комментарий; ребёнок видит
  «от учителя», без оценки и без блокировки.

**Школа:**
* Таблица классов по среднему на активного, минимум 5;
* школьный код и название; позже — кабинет школы (сводка, несколько
  учителей).
* Отчёт для школы: активность, освоенные слова, динамика, без ПДн.

**Проверки:**
* Учитель без инструкции создаёт класс за 5 минут.
* Карточки печатаются, вход по коду с карточки работает.
* Домашка видна на главной и не ломает офлайн.
* Школьная таблица не показывает класс < 5 детей.

**Готово, когда:** школа может провести «неделю слов» без вашего
участия в каждом шаге.

### 11.6 Этап 4 — шифрованный бэкап и перенос (6–10 дней)

* Экспорт профиля → AES-GCM на устройстве, ключ = 12-словный код
  восстановления (показывается один раз, родитель сохраняет).
* Сервер хранит только blob + метаданные (версия, дата, размер).
* Импорт на новом устройстве: код → расшифровка → `replaceAll`.
* Социальная привязка **не** переносится автоматически: повторный вход
  по коду класса.
* Проверка: восстановление на чистом браузере, без сервера (файл),
  с сервером (blob), при неверном коде — понятная ошибка.

**Готово, когда:** потеря телефона перестаёт быть потерей прогресса.

### 11.7 Этап 5 — по желанию (10–15 дней)

Родительские аккаунты (телефон/e-mail) и уведомления, сертификаты
класса в PDF, школьный кабинет на несколько учителей, сезонные
«чемпионаты слов», интеграция с расписанием. Всё это требует
отдельного решения по ПДн и не входит в минимальный продукт.

### 11.8 Риски сроков

| Что может съесть время | Мера |
|---|---|
| согласия и юрист | начать в этапе 0, шаблоны в §14 |

### 11.9 Как это встраивается в правила репозитория

* Каждый этап — отдельный PR в `main`, версия увеличивается
  (0.27.0 для этапа 1, 0.28.0 для этапа 2 и т.д.), заголовок
  `vX.Y.Z — …`, заметка `docs/RELEASE-X.Y.Z.md`.
* `docs/PLAN.md` — журнал (часть 50+) и решение №5a.
* `docs/HANDOFF.md` — точка передачи после каждого этапа.
* Проверки: `npm run typecheck`, `content:check`, `test:adaptive`,
  `server:test`, `test:smoke`, `build`, `test:boot`; `pickup` уже
  включает `server:test` и CI тоже.
* Новые зависимости сервера не добавляются без нужды; клиент — только
  `idb`, `react`, `zustand` (уже есть).
* Документация API — `server/README.md`; при изменении контракта
  обновляется он и §7 этого файла.

### D. План инцидента — шаблон

1. Обнаружение: кто, когда, что (алерт/сообщение/аудит).
2. Локализация: отозвать токены, закрыть доступ, сохранить логи.
3. Оценка: категории данных, число субъектов, причина.
4. Уведомление РКН — в течение 24 часов; школа/оператор — сразу.
5. Уведомление субъектов — если есть высокий риск.
6. Исправление и проверка (тест/процедура).
7. Постмортем: таймлайн, причина, меры, сроки.
8. Запись в журнал инцидентов (хранить 3 года).

### E. Расчёты

```
Событий на ребёнка/день ≈ 1,5 урока × 12 карточек × 250 Б
                        + 10 телеметрических × 250 Б
                        ≈ 7 КБ
Сырые данные/день = активные дети × 7 КБ
За 90 дней = × 90 × 1,6 (индексы/WAL)
Пик rps (средний за 3 часа) ≈ активные × 4 × 0,3 / (3 × 3600)
Всплеск: 25 детей одновременно завершают урок → 25 × 2 запроса
за ~10 секунд ≈ 5 rps (на 10 000 активных — до ~30 rps)
```

Проверка: 1 000 активных → 7 МБ/день, 0,6 ГБ/90 дней (сырые),
~1 ГБ с индексами; пик ~3 rps. 10 000 → 70 МБ/день, 6,3 ГБ/90 дней,
~10 ГБ; пик ~25 rps. Это подтверждает: одного узла хватает надолго.

### G. Глоссарий

| Термин | Значение |
|---|---|
| `install_id` | случайный идентификатор установки/браузера для анонимной телеметрии |

| RPO/RTO | допустимая потеря данных / время восстановления |
| ПДн | персональные данные |
| Оператор | тот, кто определяет цели и средства обработки ПДн |
| Обработчик | тот, кто обрабатывает по поручению оператора |
| Поручение | договор/акт, разрешающий обработку по заданию оператора |
