# Этап 2 — адаптивный объём урока в пределах родительского потолка

* Дата: **2026-09-29**, ветка `arena/01a0ec18-slovo2`
* Статус: **проектирование, ждёт согласования** (по правилу из PLAN: сначала варианты и
  согласование → затем тесты → затем код)
* Рамки: без checkpoint (этап 3), без озвучки, без свободного числового слайдера.

---

## 1. Что уже есть (этап 1) и что добавляет этап 2

Этап 1 дал **родительский потолок**: пресет `short/standard/full` = 12/16/20 базовых карточек
(`Profile.lessonSize`, `lessonCardLimit()`, по умолчанию `standard`). Потолок — жёсткий: урок
всегда строится ровно под него.

Этап 2 добавляет **адаптацию снизу**: между уроками приложение само подстраивает фактический
объём по тому, как ребёнок занимался, **никогда не превышая потолок**. Потолок по-прежнему
определяет родитель; ребёнок и так не получит «больше, чем разрешено».

```
пол (FLOOR)  ≤  эффективный объём (effective)  ≤  потолок (пресет родителя)
   8/10            меняется адаптацией               12 / 16 / 20
```

## 2. Инварианты (не обсуждаются, из PLAN)

1. Нельзя убирать: знакомство с **выбранными** новыми словами, первую попытку извлечения из
   памяти, карточку repair после ошибки.
2. Сокращение идёт в порядке: второй круг уверенных слов → дополнительный интерливинг.
3. Лимит относится к **базовой очереди**; repair-карточки в лимит не входят.
4. Прогресс-бар урока монотонный (считается от `baseTotal` на момент старта).
5. Изменение настроек применяется со **следующего запуска** урока.

## 3. Вопрос 1: когда адаптировать — варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Только между уроками** (рекомендуется) | очередь детерминирована на весь урок; монотонная полоска не затрагивается; просто тестировать; этап 3 (checkpoint) ляжет сверху без переделки | реакция запаздывает на один урок |
| B. Посреди урока («на лету» укорачивать) | мгновенная реакция на усталость | ломает `baseTotal` и монотонность (принятое решение); ребёнок видит «число уменьшилось» — недетерминированно; конфликтует с этапом 3 |
| C. A + экстренное укорачивание при выходе | — | на выходе очередь уже никому не нужна; вырождается в вариант A |

**Предложение: вариант A.** Значение читается один раз в `buildQueue()` при старте урока и не
меняется до следующего урока.

## 4. Вопрос 2: сигналы и новые данные

| Сигнал | Есть сейчас? | Что делаем |
|---|---|---|
| Завершённый урок и его точность | частично: `finishLesson(lessonId, pct)` пишет только `best` (максимум) | добавить `LessonState.lastPct` — **последний** результат |
| Ошибки | да: входят в `pct = correct/answered` (+ repair), плюс `WordState.wrong` | отдельного поля не нужно |
| Досрочный выход | **нет нигде** — выход из урока не сохраняется | добавить событие: осознанный выход при `correct+wrong > 0` и невыполненном уроке → `LessonState.quits++` |

Новые поля (все **опциональные** — старые профили работают без миграции):

```ts
// types.ts
interface LessonState {
  level: number; best: number; doneAt: number; plays: number;
  lastPct?: number;   // точность последнего завершённого прогона
  quits?: number;     // выходов, не закончив урок (после ≥1 ответа)
}
interface Profile {
  // ...
  adaptiveCards?: number; // эффективный объём после прошлой адаптации; нет поля → потолок
  adaptiveGood?: number;   // серия «хороших» уроков подряд — для повышения
}
```

**Что не считается сигналом:** выход сразу, ни на что не ответив (диалога нет, «терять нечего» —
ребёнок не познакомился с уроком); закрытие вкладки/сворачивание (ненадёжно); урок
**«Повторение»** — это тренировка, а не урок: её результат к адаптации **не относится**, иначе
тяжёлое повторение «накажет» длину обычного урока.

## 5. Вопрос 3: правило адаптации — варианты

Чистая функция `nextAdaptiveState(prev, outcome)` в `engine/scheduler.ts`; на её выходе — новое
значение `adaptiveCards` и `adaptiveGood`.

### Вариант 1 — «мягкий» (рекомендуется)

| Сигнал | Действие |
|---|---|
| досрочный выход | `−1` к объёму (не ниже пола), серия good = 0 |
| урок завершён, `lastPct < 60` | `−1`, good = 0 |
| урок завершён, `lastPct ≥ 85` | good += 1; при good ≥ 2 → `+1` (не выше потолка), good = 0 |
| всё остальное (60–84%) | без изменений, good = 0 |

Плюсы: объём меняется не чаще раза в два-три урока, «дыхание» спокойное, легко объяснить и
протестировать таблицей. Минус: из длинной серии неудач выходит медленно (по одной карточке).

### Вариант 2 — «чувствительный»

Выход → `−2`; `pct < 50` → `−2`; `50 ≤ pct < 70` → `−1`; `pct ≥ 80` → good += 1 и уже **первая**
хорошая даёт `+1`. Плюсы: быстро подстраивается. Минус: объём прыгает на ±2, ребёнок чаще
замечает разную длину урока — риск «почему вчера было длиннее?».

### Вариант 3 — «скоринг» (EMA точности → линейно в [пол, потолок]) — отклонён

Непрозрачно для родителя и ребёнка, трудно тестировать, изменения не привязаны к понятным
событиям («закрыл цель — стало короче»). Не соответствует духу решения №8 PLAN
(объяснимые варианты с плюсами и минусами).

**Предложение: вариант 1.**

## 6. Вопрос 4: пол (минимум) — варианты

| Пол | Потолок short (12) | standard (16) | full (20) | Комментарий |
|---|---|---|---|---|
| **8 (абсолютный)** | 8–12 | 8–16 | 8–20 | самый сильный диапазон; при 8 в уроке всего 3 новых слова — реально «маленький урок» |
| **10 (абсолютный)** | 10–12 | 10–16 | 10–20 | адаптация для `short` почти незаметна (всего 2 карточки) |
| **потолок − 4 (относительный)** | 8–12 | 12–16 | 16–20 | везде одинаковое «дыхание» ±4; `short` не опускается ниже 8, `full` — ниже 16 |

При выборе пола учитываем методику: меньше 8 базовых карточек — урок перестаёт ощущаться
уроком (знакомство 3 слова + закрепление + пара повторений), и checkpoint этапа 3 должен будет
в нём помещаться.

**Предложение: пол 8** (абсолютный) — одинаковый якорь для всех пресетов, самый понятный
«потолок минус сколько угодно, но не меньше 8».

## 7. Вопрос 5: что происходит при смене пресета родителем

* **(a) Кламп (рекомендуется):** `adaptiveCards` не трогаем, при старте урока
  `effective = clamp(adaptiveCards, floor, ceiling)`. Ребёнок, комфортно занимавшийся на 14 при
  потолке 16, при переходе родителя на «Короткий» получит 12; при возврате — снова 14.
* **(b) Сброс:** смена пресета обнуляет адаптацию до нового потолка. Предсказуемо, но теряет
  накопленный комфорт.

## 8. Вопрос 6: видимость — варианты

* **(a) Тихо (рекомендуется):** ничего не показываем. Ребёнок не считает карточки, родитель
  видит свой потолок как раньше.
* **(b) Строка в «Родителям»:** «Сейчас урок ≈14 карточек, потолок — 16» — прозрачно, но
  требует объяснений и текста.
* **(c) Ребёнку:** не нужно — лишние цифры во 2 классе.

## 9. Механика (как ляжет в код)

1. `engine/scheduler.ts`:
   * `ADAPT_FLOOR` (константа),
   * `effectiveCardLimit(profile)` = `clamp(profile.adaptiveCards ?? ceiling, floor, ceiling)` —
     заменяет прямой `lessonCardLimit(...)` в `buildQueue` (`LessonScreen`),
   * `nextAdaptiveState(prev, outcome)` — чистая функция правила (вариант из §5),
   * review-лимит (`maxCards / 2`, не больше 8) начинает считаться от эффективного объёма —
     отдельных правок не требует, нужен тест.
2. `state/store.ts`:
   * `finishLesson` дополнительно пишет `lastPct` и вызывает `nextAdaptiveState({kind:'finish'})`;
   * новое действие `noteLessonQuit()` — пишет `quits++` и
     `nextAdaptiveState({kind:'quit'})`; вызывается из `LessonScreen` при осознанном выходе
     через `ConfirmDialog` (диалог показывается только после `correct+wrong > 0` — сигнал
     бесплатный, тот же момент, что и сейчас);
   * `REVIEW.id` (режим «Повторение») адаптацию не трогает.
3. UI: без изменений (при варианте «тихо»); в «Родителям» при варианте (b) — одна строка.

## 10. Границы этапа 2 (чтобы не «заползло»)

**Входит:** поля профиля, две чистые функции, одна точка вызова в `LessonScreen`, тесты, журнал PLAN.

**Не входит:** checkpoint и сохранение незавершённого урока (этап 3), озвучка, слайдер,
изменение самих пресетов 12/16/20, новые экраны, изменение набора заданий и SRS.

Таблица для `nextAdaptiveState` (проверяется из smoke/чистым прогоном):

| Вход | Ожидание |
|---|---|
| quit, объём 16, пол 8 | 15, good = 0 |
| quit, объём 8 (уже пол) | 8 |
| finish pct 40 | −1 |

Смоук: урок при включённой адаптации строится не длиннее потолка; repair после ошибки всё равно
вставляется; выход через диалог увеличивает `quits`; смена пресета применяется со следующего
урока (проверка уже есть — расширить клампом).
