## Что изменилось

1. Исправлена передача контекста: 0.11.7 уже выпущена через PR #44, а не ждёт разрешения
   на коммит и публикацию. В части 28 PLAN уточнены исторические результаты: smoke 374,
   повтор с SMOKE_SEED=42, PWA 114, storage 10/10. Обновлены HANDOFF и вводный промпт.
2. По решению пользователя **каждый PR в main увеличивает версию**, включая docs/CI.
   Исключение «без релиза» убрано из README, шаблона PR и передачи контекста.
3. Добавлена CI-проверка `release:check`: стабильная версия major.minor.patch строго
   больше версии актуального main, обе версии в package-lock совпадают, есть заметка
   RELEASE для этой версии, заголовок PR начинается с `v<версия> — `.
   Проверка повторяется и при изменении заголовка PR. Номер не повышается автоматически:
   это явная часть подготовки каждого PR. Если main изменился — перед слиянием
   обновить версию и повторить проверки.
4. Добавлены тесты `test:release`: patch/minor/major и числовое сравнение, неизменная/
   меньшая/некорректная версия, рассинхронизация lock, отсутствие заметки, неправильный
   заголовок, CLI с реальным git base и ненулевой код выхода при ошибках.

Пользователь подтвердил, что сейчас сайт показывает 0.11.7: до слияния #45 это
правильная опубликованная версия. Открытие или обновление PR сайт не обновляет.
Игровой код, награды, QR-кодировщик и хранилище прогресса в этом релизе не меняются.
Заметка 0.11.7 сохранена без изменений.

## Проверки перед отправкой

Полный контур: `test:release`, `release:check` (включая заголовок), `typecheck`,
`content:check`, `test:adaptive`, `test:smoke`, `build`, `test:boot`, `audit:storage`,
`git diff --check`. Фактические результаты — в части 29 PLAN и описании PR #45.

## Проверить после деплоя

1. Дождаться успешных workflow и deployment GitHub Pages по merge-коммиту #45.
2. На сайте `?diag=1` и в «Родителям» увидеть **v0.11.8** с новым SHA.
3. В установленной PWA при необходимости принять «Доступно обновление».
   Данные приложения и прогресс не очищать.
4. Из песочницы страница Pages недоступна; живая проверка остаётся пользователю.
