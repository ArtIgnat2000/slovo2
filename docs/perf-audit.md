* Повод: на телефоне карточка урока открывается **без картинки**, картинка появляется заметно позже.

## 1. Симптом: почему карточка открывается без картинки

Цепочка в коде: ребёнок тапает урок → `LessonScreen` строит очередь → первый экран — знакомство
(`Intro`) → монтируется `<img>` из `WordArt` (`src/ui/WordView.tsx`) → **в этот момент** браузер
узнаёт URL и только теперь начинает запрос. Раньше никакого сигнала о картинке нет: нет
`<link rel=preload>`, нет `fetchpriority`, нет prefetch.

Почему запрос долгий (в порядке убывания вероятности):

| # | Причина | Механизм |
|---|---|---|
| 1 | **Конкуренция с precache сервис-воркера** | `initPWA` регистрирует SW с `immediate: true` (`src/platform/pwa.ts`) — установка стартует сразу и качает **110 файлов / ≈753 КБ** (все 94 картинки + иконки + бандл), пока ребёнок уже листает первые карточки. Запрос картинки встаёт в очередь к ~110 precache-запросам. web.dev прямо называет это проблемой: «bandwidth is precious — don't undermine critical resources by downloading secondary resources at the same time» [2]. |
| 2 | **Нет плейсхолдера** | `alt=""` + зарезервированный квадрат → пока картинка не пришла, **пустая рамка**; по приходе — резкий «поп-ин». Любая задержка сети становится видимой как «карточка без картинки». Это чисто перцептивная часть: payload крошечный (2–7 КБ), но пустота делает его заметным. |
| 3 | **Первый визит в принципе сетевой** | SW ещё не установлен → картинки идут в сеть; HTTP-кэш GH Pages живёт всего `max-age=600` (10 минут). После установки SW всё отдаётся из Cache Storage мгновенно — симптом должен исчезнуть. Если он держится и на повторных визитах — смотреть причину 4. |
| 4 | **Сеть до github.io (глобально)** | Хостинг — GitHub Pages. С **5 мая 2026** OONI фиксирует в России рост аномальных подключений к GitHub (до ~16–20% против ~4% в апреле); Роскомнадзор ограничения отрицает, но деградация CDN/подсетей обсуждается [7]. Для аудитории (2 класс, РФ) это множитель RTT **на все** запросы приложения. |

**Вывод:** симптом — сумма «обнаружение только при монтировании» + «precache ест полосу на первом
визите» + «пустая рамка вместо плейсхолдера», умноженная на задержку до GitHub. Размер самих
картинок проблемой **не является** (94 файла, 376 КБ, в среднем 4,1 КБ).

Отдельная ремарка про «повторные визиты»: если SW установлен, `initPWA` работает и офлайн-режим
включён — все картинки идут из Cache Storage и симптом исчезает. Устойчивый симптом на
**втором+** визите означает либо SW не установился (смотрите консоль/Application → Cache), либо
ребёнок открывает приложение в браузере «впервые за 10 минут» и HTTP-кэш пуст, пока precache
догоняет. Проверка: DevTools → Network → среди запросов `words/*.webp` в колонке «Size» должно
стоять «(from ServiceWorker)».

## 3. Глобальный обход: все находки

Найденыное **критично для исходного симптома**; остальное — по вкладу в отзывчивость на слабых
телефонах. «Хорошо» — что уже сделано правильно и трогать не нужно.

### 3.1 Находки

| # | Место | Проблема | Влияние | Варианты решения | Приоритет |
|---|---|---|---|---|---|
| **F1** | `WordArt` (знакомство 120px, подсказка 56px, словарик 128px) | Нет плейсхолдера, нет раннего обнаружения, нет прогрева | Напрямую симптом | (a) эмодзи-подложка + fade-in по `onLoad`; (b) `fetchpriority="high"` на карточке; (c) prefetch картинок урока в простое | **сейчас** |
| **F2** | `vite.config.ts` → `VitePWA`, `platform/pwa.ts` → `immediate: true` | Precache 753 КБ стартует до загрузки страницы | Конкуренция за полосу на первом визите (причина 1) | (a) `immediate: false` — регистрация после `load` (рекомендация web.dev [2]); (b) урезать precache до оболочки, картинки → runtime `CacheFirst` [4] + фоновая достройка (сохраняет офлайн, но сложнее и рискованнее) | **сейчас** (вариант a) / отдельно (b) |
| **F3** | Хостинг GH Pages | Деградация доступа к GitHub в РФ (май 2026) [7]; `max-age=600` | Медленнее **всё**, включая первый визит | (a) ничего: документировать; (b) зеркало Cloudflare Pages / Netlify (SW и манифест переносятся без изменений, base поменять); (c) замерить реальный RTT с телефона | решить отдельно |
| **F4** | `main.tsx`: `await rehydrate()` до первого `render` | Первый рендер ждёт IndexedDB | Пустой экран на старте (обычно десятки мс, на слабых — заметно) | splash-фон и логотип прямо в `index.html` (инлайн-стили, рисуется до JS); при желании — таймаут ожидания | низкий |
| **F5** | `WordsScreen`: 94 превью `<img>` сразу при открытии вкладки | Все запросы/декодирование разом, без `loading="lazy"` | Джанк и сетевой всплеск на первом открытии «Словарика» | `loading="lazy"` + `fetchpriority="low"` на превью | низкий |

| **F7** | `app.css`: `backdrop-filter: blur(2px)` на полноэкранном оверлее диалога | Самая дорогая CSS-операция на слабых GPU | Просадка кадров при открытии «Выйти из урока?»/покупке | полупрозрачный фон без blur (визуально почти идентично при 2px) | низкий |
| **F8** | Бандл один чанком 242 КБ (80 gzip) | На текущем объёме — норма; запаса на рост нет | Первый визит | Ничего не делать до появления ленивых экранов; при росте — динамический `import` экранов | наблюдать |
| **F9** | `Confetti` инжектит `<style>` с keyframes при каждом рендере | Мелочь | Копеечный оверхед | keyframes перенести в `app.css` | копеечно |

### 3.2 Что уже хорошо (не трогать)

* `width`/`height` у всех `<img>` → **нет CLS** от картинок [3].
* Картинки крошечные (WebP 256×256, ≤9 КБ) — правильный формат и размер.
* Селекторы zustand возвращают стабильные ссылки (урок #185 выучен) — ререндеров-«кручений» нет.
* Звук синтезируется Web Audio — ноль файлов, ноль сетевых запросов.
* Нет внешних шрифтов, аналитик, трекеров; CSS 4,7 КБ gzip.
* Словарик — 94 элемента: виртуализация не нужна (порог — сотни–тысячи).
* Каждый экран урока — локальный state, подписки на стор точечные — INP-паттерны соблюдены [5].

### 3.3 Явно не делаем

* **React.memo/useTransition по всему дереву** — симптомов (длинных тасков, лагов тапа) в коде не
  видно, профилировщик недоступен; оптимизация вслепую = риск регрессии без выигрыша.
* **Code-splitting экранов** — не окупается на 80 КБ gzip (см. F8).
* **LQIP/blur-up- miniature** — избыточно для иконок 4 КБ: хватает эмодзи-подложки.

## 4. Пакеты вариантов (для выбора)

| Пакет | Что внутри | Плюсы | Минусы | Трудоёмкость |
|---|---|---|---|---|
| **A. «Восприятие»** | F1a (эмодзи-подложка + fade-in), F1b (`fetchpriority`), F5 (`loading="lazy"` на превью) | Карточка **никогда не пустая**; эффект виден сразу и без сети; ничего не ломается; час работы | Приход картинки не ускоряет — только перестаёт бросаться в глаза | ~1 ч |
| **B. «Готовность»** | A + F1c: prefetch картинок *текущего* урока на главной в простое (`requestIdleCallback` c fallback на `setTimeout` — Safari его не поддерживает) и повторный прогрев при старте урока | К моменту открытия карточки картинка уже в кэше браузера → приход «мгновенный», в т.ч. на первом визите | +несколько запросов на главной (крошечные, в простое) | ~2–3 ч |
| **C. «Первый визит»** | B + F2a (SW регистрируется после `load`); **опционально** F2b: урезать precache до оболочки (−376 КБ), картинки → runtime `CacheFirst` + тихий прогрев всех 94 после загрузки | Разгружает критический путь первого визита; precache перестаёт драться с первыми картинками | F2b меняет офлайн-гарантию: часть картинок попадёт в кэш только после фонового прогрева — нужна отдельная проверка офлайна | a: ~1 ч; b: ~4 ч + офлайн-чек |
| **D. «Хостинг»** | F3: замер RTT с телефона, при подтверждении — зеркало на Cloudflare Pages (или вернуть GH Pages как запасное) | Лечит задержку для РФ-аудитории глобально, включая всё приложение | Нужен аккаунт/решение; деплой-процесс меняется | решение ≠ код |

**Рекомендация:** A + B сейчас (без риска для офлайна, закрывают симптом с двух сторон),
C-a — следом за ними одним же PR, C-b и D — отдельными решениями с проверкой.

## 5. Экспертные источники (что взяли)

1. **web.dev — Service worker registration** [1]: отложить регистрацию SW до загрузки страницы;
   install-handler не должен драться за полосу с критическими ресурсами первого экрана.
   → обоснование C-a и одной из причин симптома.
2. **Chrome for Developers — LCP request discovery** [2]: раннее обнаружение картинки,
   `fetchpriority="high"`, без `loading="lazy"` на ключевом изображении. → F1b.
3. **web.dev Learn — Images: performance issues** [3]: `width/height` против CLS; загрузка
   «пустой рамки» — вредна для восприятия; lazy — только ниже сгиба. → F1a, F5.
4. **Workbox recipes (imageCache)** [4]: картинки — `CacheFirst` в runtime-кэш, а не обязательно
   precache. → вариант F2b.
5. **Реальный кейс: PR «trim the precache to the app shell»** [5]: хвост precache на холодном
   визите до 15 с при 1,2 МБ; после обрезки — первая отрисовка не спорит с установкой SW.
   → почему F2 вообще в таблице.
6. **web.dev — INP / React-практики** [6]: стабильные пропы и селекторы, локальный state,
   отсутствие длинных тасков. → раздел 3.2: React-слой трогать не нужно.
7. **vc.ru — доступность GitHub в РФ, май 2026** [7]: OONI фиксирует деградацию с 5 мая 2026. → F3.

## 6. Как проверяем после правок

1. `npm run typecheck && npm run content:check && npm run test:smoke && npm run build && npm run test:boot`.
2. Прогрев: на главной в консоли/сети видим запросы `words/*.webp` в простое (пакет B).
3. Свежий профиль (инкогнито): открыть урок — картинка знакомства либо уже пришла (прогрев),
   либо с первой же отрисовки видна эмодзи-подложка; пустой рамки не бывает.
4. `sw.js` после сборки: если выбран C-b — в precache нет `words/*.webp`, есть runtime-правило;
   офлайн (DevTools → Offline, перезагрузка) — все экраны и картинки работают.
