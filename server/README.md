# Пилотный сервер «СЛОВО 2.0»

Маленький API для классных соревнований и обезличенной телеметрии.
Это **референс-реализация** плана [`docs/proposals/backend-social-plan.md`](../docs/proposals/backend-social-plan.md),
а не финальный прод: здесь нет кабинетов учителя и родителей, нет
PostgreSQL и нет UI. Зато есть живой контракт, который можно поднять
на Synology за пять минут и проверить на одном классе.

```
server/
  src/app.mjs        маршруты, права, подсчёт звёзд, телеметрия
  src/db.mjs         схема SQLite, ретенция
  src/util.mjs       токены, коды, дни и периоды
  src/main.mjs       чтение окружения, HTTP, graceful shutdown
  scripts/backup.mjs горячий бэкап (node:sqlite backup API)
  test/             12 контрактных тестов продуктовых инвариантов
  Dockerfile         node:22-alpine, без npm install
  docker-compose.example.yml
  compose.env.example
```

Зависимостей рантайма **нет** — только встроенные модули Node 22
(`node:http`, `node:crypto`, `node:sqlite`). Поэтому образ собирается
копированием файлов, а `npm audit` тут нечего проверять.

## Быстрый старт

```bash
cd server
ADMIN_TOKEN="$(openssl rand -base64 32)" DB_PATH=/tmp/slovo.db npm start
```

В другом терминале:

```bash
ADMIN=... # тот же токен

# 1. Создать класс (делает оператор/админ, не учитель)
curl -s -X POST localhost:8080/v1/admin/classes \
  -H "x-admin-token: $ADMIN" -H 'content-type: application/json' \
  -d '{"schoolCode":"school-42","schoolName":"Школа №42","label":"2 «А»","goalStars":100}'

# 2. Ребёнок входит по коду класса — только с отметкой согласия
curl -s -X POST localhost:8080/v1/join -H 'content-type: application/json' \
  -d '{"code":"ABC234","consent":true,"consentVersion":"2026-10-21","nickname":"Звёздочка"}'

# 3. Отправить пачку событий (офлайн-очередь шлёт так же)
curl -s -X POST localhost:8080/v1/sync \
  -H "authorization: Bearer $CHILD_TOKEN" -H 'content-type: application/json' \
  -d '{"events":[
        {"id":"evt-0001-aaaa","type":"mastered","wordId":"g2_Москва"},
        {"id":"evt-0002-aaaa","type":"lesson","tasks":12,"correct":11,"wrong":1,"activeSeconds":200}
      ]}'

# 4. Таблица класса и школы
curl -s 'localhost:8080/v1/board?period=week' -H "authorization: Bearer $CHILD_TOKEN"

# 5. Метрики для разработчиков
curl -s 'localhost:8080/v1/admin/metrics?days=30' -H "x-admin-token: $ADMIN"
```

Тесты:

```bash
cd server && npm test
```

## Маршруты

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| GET | `/healthz` | все | живость, версия согласия, потолок звёзд |
| POST | `/v1/admin/classes` | админ | создать класс, выдать код |
| GET | `/v1/admin/classes` | админ | список классов и кодов (для оператора) |
| POST | `/v1/admin/classes/:id/rotate-code` | админ | сменить код класса |
| POST | `/v1/join` | ребёнок | войти по коду + согласие → токен устройства |
| POST | `/v1/sync` | ребёнок | пачка событий (≤100), идемпотентно |
| GET | `/v1/board?period=week\|30d\|all` | ребёнок | пьедестал класса + я + школа |
| DELETE | `/v1/me` | ребёнок | удалить свои данные |
| POST | `/v1/telemetry` | приложение | анонимные события (≤200) |
| GET | `/v1/admin/metrics?days=30` | админ | агрегаты для разработчиков |

Ошибки — `{ "error": { "code": "snake_case", "message": "по-русски" } }`.
Коды `400/401/404/409/413/429/500`; 401 на `/v1/board` означает, что
токен отозван или данные удалены — клиент показывает «класс отключён»,
но обучение продолжается локально.

## Продуктовые инварианты (их и проверяют тесты)

1. **Согласие — до данных.** Без `consent: true` и актуальной версии
   текста `/v1/join` отвечает 400/409; сервер хранит версию и дату.
2. **Нет имён.** В базе только псевдоним (по умолчанию «Ученик N»),
   аватар из белого списка и учебные результаты. Имя ребёнка, школа
   в смысле «класс + учитель» и контакты не запрашиваются.
3. **Потолок 10 звёзд в день.** 12 освоенных слов дают 10 звёзд:
   рейтинг не награждает за многочасовую зубрёжку.
4. **Идемпотентность.** Каждое событие имеет `id`; повтор после
   обрыва сети даёт `duplicates`, а не двойные звёзды.
5. **Часы не решают.** Событие «из будущего» отклоняется,
   события старше 14 дней — тоже; день берётся из события,
   но проверяется окном ±1 день (часовые пояса России).
6. **Школа сравнивает среднее**, а не сумму: класс из 5 человек
   с 3 звёздами на каждого обходит класс из 30 человек с 2.
   Класс с менее чем 5 активными детьми в таблицу школы не попадает.
7. **Видно пьедестал и себя.** Полный список класса наружу не отдаётся:
   у ребёнка нет публичного «последнего места».
8. **Удаление — настоящее, а не флаг.** `DELETE /v1/me` удаляет
   ребёнка, ответы, звёзды и токен; в журнале остаётся хеш id.
9. **Псевдоним уникален в классе** без учёта регистра: вход с занятым
   псевдонимом — `409 nickname_taken`. Иначе в таблице две «Звёздочки».
10. **Сырые ответы живут 90 дней**, затем удаляются; звёзды и дни —
    до 400 дней, дальше сезон закрывается. В ответах нет введённого
    текста, только `correct`/`hint`/`ms`.
11. **Телеметрия — белый список** имён событий и плоских свойств:
    вложенные объекты, свободный текст и имена отбрасываются.

## Что сознательно не сделано

* **Кабинет учителя.** Класс создаёт оператор через админ-токен.
  Учительские аккаунты, вход по паролю, выпуск кодов из ростера —
  этап 3 плана: там же появляются карточки учеников и домашка.
* **Проверка слов по контент-паку.** Сервер не знает списка 94 слов
  и принимает любой `wordId` формата `g2_…`. Потолок и дедупликация
  ограничивают накрутку, но не подделку. На этапе 2 в сборку
  добавляется манифест `content hash` — см. план, §8.
* **PostgreSQL и горизонтальное масштабирование.** SQLite в WAL
  держит сотни классов на одном узле; переезд — в плане, §9.
* **Push, e-mail, восстановление пароля.** В пилоте нет ни почты,
  ни телефона — значит, и восстанавливать нечего.
* **UI.** Экраны класса и «Родителям → Приватность» — отдельная работа
  на клиенте; контракт готов.

## Развёртывание на Synology

1. DSM 7.2+, пакет **Container Manager**.
2. Скопируйте папку `server/` в `/volume1/docker/slovo-api`.
3. `compose.env.example` → `compose.env`, задайте `ADMIN_TOKEN`
   (`openssl rand -base64 32`) и `ALLOWED_ORIGINS`. Файл — `chmod 600`.
4. `docker-compose.example.yml` → `docker-compose.yml`, проект →
   «Создать» → запустить.
5. Наружу — **только** через DSM Reverse Proxy (HTTPS, Let's Encrypt)
   или Cloudflare Tunnel. Порт 8080 в интернет не публикуйте.
6. Ежедневный бэкап — Планировщик задач DSM:
   `docker exec slovo-api node --disable-warning=ExperimentalWarning scripts/backup.mjs`
7. Раз в неделю копируйте `/data/backups` на другой носитель.
   Бэкап на том же диске не защищает от потери диска.

### Про Cloudflare Tunnel и персональные данные

Туннель решает проблему CGNAT и динамического IP, но трафик проходит
через зарубежную инфраструктуру. Для пилота на данных своей семьи это
приемлемо; для школы это вопрос трансграничной передачи и локализации
(152-ФЗ, ст. 18 ч. 5) — до подключения реального класса нужен
российский хостинг или письменное заключение юриста. Подробнее — §10
плана.

### Если `node:sqlite` недоступен

В старых тегах `node:22-alpine` модуль мог быть собран без SQLite.
Проверка в контейнере:

```bash
docker run --rm node:22-alpine node -e "require('node:sqlite'); console.log('ok')"
```

Если команда падает — обновите тег Node (22.13+ / 24) или перейдите
на сборку с PostgreSQL; контракт API от этого не меняется.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8080` | порт HTTP |
| `HOST` | `0.0.0.0` | интерфейс (в контейнере) |
| `DB_PATH` | `/data/slovo.db` | файл SQLite |
| `ADMIN_TOKEN` | — | обязателен, ≥24 символов |
| `ALLOWED_ORIGINS` | — | CORS-список через запятую |
| `TZ` | `Europe/Moscow` | границы недели и дни |
| `TRUST_PROXY` | `0` | брать реальный IP из `X-Forwarded-For` (только за своим прокси) |
